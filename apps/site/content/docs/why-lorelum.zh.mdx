代码能运行，仍可能缺失工程边界。登录页可以正常渲染，却把 HTTP 请求和 token 持久化都放在组件里。范围明确的 UI 改动也可能在规划阶段就被加入额外行为、抽象和测试，而用户并未要求这些工作。

这些问题背后是知识与判断缺位：相关指导没有带着适用边界，在 Agent 规划或行动的时刻可靠抵达它。

## 让指导对应当前判断

项目指令仍适合记录长期有效的仓库规则。可复用的工程经验还需要一种方式，让 Agent 根据当前任务选择相关内容。

Lorelum 将经验组织成 Practice，按需检索。查询可以同时说明目标、范围、风险，以及当前需要做出的判断：

```sh
lore query "我正在按现有设计实现设置卡片，准备确定改动范围、实现计划和验证方式。"
```

Agent 用 `lore get` 读取相关结果，结合设计和仓库检查适用条件，再用这些指导让计划与需求规模相称。

## 支持团队与个人开发者

团队可以为自己的标准和反复出现的决策维护 Practice。Vibe coder 和小团队可以安装共享 Knowledge Pack，获得自己尚未积累的工程经验。

Pack 可以版本化管理，也能在不同的命令型 Agent 中使用。[Skill](./agent-setup)说明何时检索，CLI 提供一致的检索和读取接口。

## 随工作变化重新检索

同一任务在实现前可能需要范围指导，上下文丢失后需要恢复指导，宣布完成前需要验证指导。调用方可以针对这些时刻再次查询。

Lorelum Core 不读取完整会话，也不控制 compaction。生命周期集成取决于宿主能力。[宿主 Plugin](./agent-setup) 在受支持的生命周期事件或模型请求中提供已安装 Pack 目录，具体范围见宿主功能对比；项目研究中讨论的更完整压缩指导，并不是所有宿主中都已实现的能力。

## 调用方继续对结果负责

检索提供相关指导，不提供实现正确的证明。Agent 仍需阅读代码、遵循用户范围，并验证所请求的结果。是否将某项建议用于当前任务，应由 Practice 的适用条件和实际任务共同决定。

从[快速开始](./quickstart)配置环境，再通过[检索与应用 Practice](./retrieval)将指导用于实际工作。
