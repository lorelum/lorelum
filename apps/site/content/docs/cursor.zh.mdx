Lorelum Plugin 会为 Cursor 提供工程指导和 `/lore` 命令。

## 开始前

请先完成[快速开始](./quickstart)。运行 Cursor 的环境需要能使用 `lore` 命令，并且至少安装了一个 Pack。

## 安装

1. 在 Cursor 中打开 **Customize**。
2. 当 marketplace 中出现 **Lorelum** 时直接安装，或将 Lorelum 仓库（`lorelum/lorelum`）或本地 checkout 添加为 marketplace。
3. 在 `lorelum-plugins` 中安装 **Lorelum**。
4. 启动一个新会话。

想在 marketplace 之外试用本地副本时，把 Plugin 目录放到 `~/.cursor/plugins/local/lorelum` 并重新加载 Cursor。请使用真实副本而不是指向 checkout 的符号链接：Cursor 只加载目标位于该目录内部的符号链接。

## 使用 Lorelum

确认命令菜单中出现 `/lore`。你可以运行：

```text
/lore 这个改动应该怎样验证？
```

也可以要求 Cursor 在确定重要决定前使用 Lorelum。

Cursor 在新会话开始时注入 Installed Pack Catalog，但不等待注入完成，因此 Catalog 可能不会立刻可见。Lorelum Skill 会复用可见的 Catalog；不可见时用一次 `lore pack list --details` 自行建立，无需你手动执行。



Cursor 会话还会记录已读 Practice 候选。当 agent 在会话内成功执行
`lore get` 时,CLI 会把该 Practice 的元数据报告给正在运行的 Backend,并写入
`~/.lorelum/sessions/cursor/<会话 ID>/practice-reads.jsonl`。上报是可选行为:
它不会启动 Backend,也不会改变 `lore get` 的结果。

当 Cursor 的 Shell 工具执行含 `lore` 字样的命令时,命令前会被加入两行
`export`,携带宿主与会话身份 —— 已读记录正是借此关联到当前对话。该前缀不
改变命令的批准流程、参数或退出码,也不会注入到其他工具。哪些命令会被加前
缀由共用的
[`agent.shellSessionInjection`](./configuration#agent-shell-会话身份) 配置决定。
Cursor 的子 Agent 目前收不到已读候选提示:subagentStart 的响应无法携带注入
的上下文,因此该宿主没有可用的提示通道。

## 功能支持情况与限制

Cursor 提供 Skill、CLI query/get、成功读取关联和异步 Main Catalog。Catalog 属于部分交付能力：首轮可能早于 Hook 返回，缺少可见目录时 Skill 为任务列一次 Pack。

**compact 后不刷新 Main 已读候选。** Cursor 不会在此时重跑 `sessionStart`；`preCompact` 的返回值只向用户显示消息，不进入模型上下文。保留会话开始时注入的内容，不等于更新后来新增的阅读候选。需要指导时照常 query/get；记录一次读取本身不会把它重新交给 Main。

Plugin 也不向子 Agent 提供已读提示或独立 Catalog。各项差异见[宿主功能对比](./agent-setup#宿主功能对比)。


## 更新

在 **Customize** 中选择 Lorelum，安装可用更新。以 Lorelum 仓库为源的 marketplace 会从其跟踪分支获取更新；本地副本则替换 `~/.cursor/plugins/local/` 下的目录并重新加载 Cursor。

## 排查问题

如果没有出现 `/lore` 或工程指导：

1. 确认 Lorelum 已在 **Customize** 中安装并启用。
2. 确认 Cursor 运行环境中的 `lore --version` 可用。
3. 安装或更新后启动一个新会话。

检索或模型问题请查看[故障排查](./troubleshooting)。
