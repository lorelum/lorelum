Lorelum 帮助编码 Agent 在工作过程中找到相关的工程指导。请先完成[快速开始](./quickstart)，确保运行 Agent 的环境已经有 `lore` 命令和至少一个 Pack。

## 选择你的 Agent

| Agent                  | 推荐接入方式                          |
| ---------------------- | ------------------------------------- |
| Codex                  | 安装 [Lorelum Plugin](./codex)。      |
| WorkBuddy              | 安装 [Lorelum Plugin](./workbuddy)。  |
| ZCode                  | 安装 [Lorelum Plugin](./zcode)。      |

| 其他能执行命令的 Agent | 使用宿主支持的 Skill 机制或项目指令。 |

## 宿主功能对比

所有官方 Plugin 都使用同一套 Lorelum Skill、`lore query` 和 `lore get`。请逐项比较能力；安装了 Plugin 不代表宿主具备所有生命周期功能。

当 Agent 已在使用任务或计划工具时，Skill 会要求它把完整读过的 Practice 中适用于后续步骤的具体指导带到对应节点，并据此检查实际工作。对于可预见但仍需要指导的实质性决策，Skill 也会要求记录具体检索问题和时机，例如编码前查询项目相关的实现约束，或确定验收方式前查询测试边界。到节点时，Skill 要求 Agent 重新判断是否仍需检索，完整读取准备采用的 Practice，并在适用时使用；不要求在每次编辑或测试前机械查询。工具无法安全注释已有步骤时，可以追加关联该节点的简短具体检查项，不替换原有任务。工具是否可用、计划是否保留取决于宿主和会话。Lorelum 不要求仅为提醒创建计划；提醒不能代替读取 Practice 全文或判断其适用性。

修改已有计划前，Agent 应先查看当前计划，而不是初始化替代计划并重置阶段或状态。在 omp 中，`todo` 的 `op: "view"` 用于查看计划，`init` 会替换计划。如果不能安全查看或更新，Agent 应在工作上下文中承接指导。

完整读取的 Practice 如果影响已有步骤（包括正在进行的步骤），Skill 会要求 Agent 在继续工作前记录具体指导。在 omp 中，Agent 可以向现有阶段追加检查项，而不替换计划。

贯穿整个任务，Skill 指引 Agent 判断当前具体决策是否存在指导缺口：设计和规划期间、规划完成后首次编码前、设计或编写测试前、首次选择测试运行方式前、失败诊断或返工前，以及验收决策前。即使没有计划或任务工具，Skill 也要求进行判断。仍需发现指导时，Skill 要求针对具体情境和决策使用语义 `lore query`；已知精确的 Practice ID 可以直接用 `lore get <practice-id>` 读取，但若仍需发现其他相关指导，这次读取不能代替查询。已读指导仍适用时可以复用。查询只用于寻找候选，不能代替全文：应用某个 Practice 前应完整读取。

这些是对 Agent 的指引，不是宿主强制保证。Agent 仍可能遗漏指导、跳过检查，或违反 Skill 的要求修改已有计划；有此风险时请检查实际操作和计划。

在每个相关决策点，Skill 要求 Agent 明确当前工作需要回答的问题；一般性指令、Catalog 条目或针对其他决策的查询本身不能证明当前问题已解决。适用指导应先用于当前决策和工作，再继续后续步骤。计划中追加在后面的前置检查，应在目标步骤之前执行；检查已完成工作的事项则应留在工作之后。

例如，为支付重试改动编写测试前，Agent 可以查询超时与并发重试的测试边界，再读取相关结果的全文后设计测试。选择运行方式前，它应重新判断是否需要测试环境方面的指导；仍需发现时，Skill 要求针对该决策查询。它可以直接读取已知精确 ID 的 Practice，但如果还需要发现其他指导，仍需查询；已读指导适用时则可以复用。后续失败或验收决策也需要同样判断，而不是自动重复先前查询。

Cursor 的 Catalog 异步到达，首轮可能看不到；缺少且当前决策需要发现未知指导时，Skill 会要求 Agent 为任务列一次 Pack。仅需读取已知精确 Practice ID 时不必为此建立 Catalog。omp 的子 Agent Catalog 需要显式设置 `agent.subagentPackCatalog: true`，与已读提示独立；所有嵌套 task/eval 子 Agent 沿用源头 Main 的候选，自己的读取仍归自己的会话。

会话关联要求 get 成功、Backend 已在运行且身份有效。共用的[shell 设置](./configuration#agent-shell-会话身份)决定哪些命令传递身份；漏记不改变 get 结果。候选只是有界历史元数据，不是完整正文或采纳证明。Main 压缩恢复只使用已有 compact 事件，不在 startup/resume 额外再发一遍。各 host 指南说明具体入口、限制和恢复方式。

## 其他 Agent

能够执行命令的 Agent 可以调用同一套 CLI。按宿主支持的方式安装 Skill；若宿主使用项目指令，则将 Skill 的检索指导放入对应指令文件。

核心行为是：用 `lore query` 描述任务和当前判断，用 `lore get` 读取相关结果，再按适用条件应用指导。Agent 直接阅读默认 text，而不解析其排版。取回的 Practice 包含 `resource:` link 时，已安装 Skill 会说明如何用显示出的可变 current `packRoot` 解析它、按需读取 reference、复制 asset 后编辑，以及只在当前任务授权下显式运行 script。只有结果异常、需要排查或核对 protocol 细节时才使用 `--json`。完整执行约定见 [Agent 使用说明](./agents)。

## 第一次使用

启动一个新任务，告诉 Agent：

```text
请在确定这个任务的计划前，用 Lorelum 查找相关的工程指导。
```

当设计、实现、验证或恢复需要工程判断时，Agent 会使用已安装的指导。

## 会话中的已读候选

Lorelum 可以为 Agent 对话保留一份简短的已读 Practice 候选列表。`lore get` 成功、本机 Backend 已在运行，且宿主集成能将读取关联到会话时，CLI 才报告这次读取。宿主可以向命令传递会话身份，也可以使用受支持的活动窗口后备。列表由 Backend 存在 `~/.lorelum/sessions/<宿主>/<会话 ID>/practice-reads.jsonl`；重启 Backend 或删除原 worktree 不会清除记录。读取失败或无法关联会话就不记，不改变 `get` 的结果。

支持子 Agent 上下文入口的宿主可以把候选 ID、标题和适用条件传给新子 Agent。omp 在 task/eval 的模型请求中提供，Codex 与 Claude Code 使用子 Agent 启动 Hook。子 Agent 自行决定是否 `lore get`，不会自动注入正文。列表可能不完整，只说明某个 Practice 被读过，不代表主 Agent 已采纳；它不是任务日志或权限依据。各宿主 Plugin 分别说明支持的接入方式。

Claude Code、Codex、WorkBuddy 和 omp 还会在 compact 后刷新 Main 候选；Agent 只在当前任务需要时重新读取全文。没有候选或 Backend 不可用不会阻塞继续任务，也不为恢复提示自动启动 Backend。Cursor 与 ZCode 没有压缩后刷新入口，仍可正常 query/get。

支持在 shell 命令中传递会话身份的宿主共用[注入范围配置](./configuration#agent-shell-会话身份)；各宿主指南说明对应的 Hook 行为。

## 没有生效怎么办

1. 在 Agent 实际运行命令的环境中确认 `lore --version` 可用。
2. 确认 Skill 或 Plugin 已安装并启用。
3. 安装或更新 Plugin 后，启动一个新任务。
4. 如果 Lorelum 可以启动但无法检索指导，查看[故障排查](./troubleshooting)。

## 更新

文件安装的 Skill 直接用最新版 `SKILL.md` 替换即可。Plugin 通过宿主的插件机制更新，具体步骤见各自的安装页。
