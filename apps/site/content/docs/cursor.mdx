The Lorelum Plugin adds engineering guidance and the `/lore` command to Cursor.

## Before you start

Complete [Quickstart](./quickstart). The `lore` command must be available to
Cursor, and you need at least one installed Pack.

## Install

1. In Cursor, open **Customize**.
2. Install **Lorelum** from `lorelum-plugins` when it is listed in the
   marketplace, or add the Lorelum repository (`lorelum/lorelum`) or your local
   checkout as a marketplace.
3. Install **Lorelum** from `lorelum-plugins`.
4. Start a new conversation.

To try a local copy without a marketplace, place the Plugin directory in
`~/.cursor/plugins/local/lorelum` and reload Cursor. Use a real copy rather
than a symlink to a checkout: Cursor only loads symlinks whose target resolves
inside that folder.

## Use Lorelum

Check that `/lore` appears in the command menu. You can run:

```text
/lore How should I verify this change?
```

Or ask Cursor to use Lorelum before it finalizes an important decision.

Cursor injects the Installed Pack Catalog when a new conversation starts
without waiting for it, so the Catalog may not be visible right away. The
Lorelum Skill reuses a visible Catalog and otherwise builds one with a single
`lore pack list --details`; you do not need to run it yourself.



Cursor sessions also record read Practice candidates. When your agent
successfully runs `lore get` inside the session, the CLI reports the Practice
metadata to a running Backend, which stores it under
`~/.lorelum/sessions/cursor/<session id>/practice-reads.jsonl`. Reporting is
optional: it never starts the Backend and never changes the `lore get` result.

When Cursor's Shell tool runs a command that mentions `lore`, the command is
prefixed with two `export` lines that carry the host and session identity —
this is how the read is associated with the conversation. The prefix does not
change the command's approval flow, arguments, or exit status, and it is not
added to other tools. Which commands get the prefix follows the shared
[`agent.shellSessionInjection`](./configuration#agent-shell-session-identity)
setting. Subagents do not receive read-candidate hints on Cursor: the
subagentStart response cannot carry injected context, so no hint channel
exists there.

## Supported features and limits

Cursor provides the Skill, CLI query/get, successful-read association, and an asynchronous Main Catalog. Catalog delivery is partial: the first turn can precede the Hook result, so the Skill lists Packs once when no Catalog is visible.

Main read candidates are **not refreshed after compact**. Cursor does not rerun `sessionStart` then, and `preCompact` returns a user-facing message rather than model context. Retaining context injected at session start does not refresh candidates read later in the conversation. Continue to query/get guidance normally when it is useful; recording a read does not by itself deliver it back to Main.

The Plugin also does not deliver child read hints or a separate child Catalog. See the [host capability table](./agent-setup#host-capabilities).


## Update

Open **Customize**, select Lorelum, and install the offered update. A
marketplace backed by the Lorelum repository picks up updates from the branch
it tracks; for a local copy, replace the directory under
`~/.cursor/plugins/local/` and reload Cursor.

## Troubleshoot

If `/lore` or guidance is missing:

1. Confirm Lorelum is installed and enabled under **Customize**.
2. Confirm `lore --version` works in the environment used by Cursor.
3. Start a new conversation after installing or updating.

For retrieval or model problems, see [Troubleshooting](./troubleshooting).
