`lore` CLI 默认向 stdout 输出可读 text，包括 help 和 version。`pack list`、`query`、`get` 的默认 text 是按当前判断精简的视图：保留这一步需要的指导、状态和 source locator，不重复全部 metadata。对这些命令使用 `--verbose` 可查看完整结果 data 的 text；需要完整、单行且可机读的 envelope 时使用 `--json`。Agent 可直接阅读默认 text，但不能解析其排版。诊断和进度输出到 stderr；默认命令失败也输出到 stderr，并附带该原始调用的本机 `diagnostics.traceId`。

## 命令目录

| 命令 | 用途 |
| --- | --- |
| [query](./reference/query) | 围绕任务和时刻检索 Practice 摘要。 |
| [get](./reference/get) | 读取已安装 Practice 的全文。 |
| [pack](./reference/packs) | 安装、列出、更新和移除 Pack。 |
| [index](./reference/indexing) | 检查、构建和重建 semantic index。 |
| [model](./reference/model) | 检查、加载和卸载 embedding 模型。 |
| [backend](./reference/backend) | 启动、检查和停止本地服务。 |
| `logs` | 按 source、level 或 trace 查看受管理的本机日志；`logs prune` 只清理过期的 Lorelum 日志文件。 |
| `feedback draft` | 生成可审阅的本地 bug 或 improvement 草稿；不会提交 Issue 或上传诊断。 |
| [validate、format、i18n sync](./reference/authoring) | 验证 Pack 内容并维护本地化。 |
| `describe` | 返回命令能力和 schema。 |

## 查询已安装版本的合同

```sh
lore describe --json
lore describe query --json
lore describe index.build --json
lore --help --json
lore --version --json
```

`describe` 返回参数、选项、结果 schema、错误码和退出码。嵌套命令使用点号标识：`index.build` 对应 `lore index build`。

针对某个发行版本编写自动化时，以已安装的 schema 为准。Alpha 版本可能调整命令合同。

## 全局选项

| 选项                  | 用途                                               |
| --------------------- | -------------------------------------------------- |
| `--store-root <path>` | 选择 Pack、query、get 和 index 命令使用的 Store。  |
| `--debug`             | 仅为本次调用记录 debug 级本机日志，不改写配置。    |
| `--log-level <level>` | 设置 stderr 诊断级别，默认 `error`。               |
| `--json`              | 返回完整、单行的 JSON protocol envelope。          |
| `--help`、`-h`        | 显示可读 Help；需要能力数据时追加 `--json`。       |
| `--version`、`-V`     | 显示工具/协议版本；需要 envelope 时追加 `--json`。 |

相对 Store 路径基于当前工作目录解析。相关命令应使用同一个 root：

```sh
lore --store-root /path/to/store pack list
lore --store-root /path/to/store query "评审一个局部 UI 修改的需求范围"
lore --store-root /path/to/store query "评审一个局部 UI 修改的需求范围" --json
```

模型配置和 Backend 运行状态仍属于用户级环境。详细说明见[配置](./configuration)。

若要让发行版或自动 Hook 持续记录详细信息，可在 `~/.lorelum/config.yaml` 设置 `logging.level: debug`。`lore --debug` 还会把这一次调用的 detail 只传给关联的 authenticated Backend request 和 lifecycle；它不会改写 daemon 全局等级，也不会影响并发调用。它和仅控制 stderr 的 `--log-level` 是两件事。

## 本机日志

普通 text failure 会显示 `diagnostics.traceId`，`--json` 响应也会在 envelope 中携带同一字段。复制该 ID 后即可查看原始调用，不必直接读取 Backend 私有文件：

```sh
lore logs --trace-id <traceId> --limit 100
lore logs --source hook.codex --level debug
lore logs prune
```

日志保存在 `~/.lorelum/logs/`。`lore logs` 不会启动 Backend/model；缺失、轮转或损坏文件会作为证据限制返回，不会用其他调用内容填充。完整的 trace、debug 重现和 feedback 路径见[故障排查](./troubleshooting)。

## JSON 响应结构

下面的 envelope 字段只在选择 `--json` 时存在。不要解析默认 text。JSON 与 text 使用同一次 handler result 和同一个退出码；上述三个决策视图还会省略非决策 data 字段，具体见各命令参考。`--verbose` 可在 text 中恢复完整 data，不改变 JSON。

每个 `--json` CLI envelope 都包含 `protocolVersion`、`toolVersion`、`command`、`diagnostics.traceId` 和 `ok`。Hook 保持宿主自己的 envelope，不会暴露这项 trace metadata。

| 字段 | 含义 |
| --- | --- |
| `protocolVersion` | JSON 协议版本。 |
| `toolVersion` | 已安装 CLI 的版本。 |
| `command` | 生成结果的命令标识。 |
| `diagnostics.traceId` | 本次调用的本机关联 ID；它不是鉴权凭证，也不是公开分享 ID。 |
| `ok` | 本次调用是否产生成功的命令结果。 |
| `data` | 成功时的命令结果。 |
| `error.code` | 失败时的稳定错误标识。 |
| `error.message` | 失败时供人阅读的原因说明。 |
| `error.recovery` | 可用时提供 Backend 恢复操作。 |
| `error.details` | 失败时可选的非空 validator-owned 机器诊断事实数组。 |

程序应按错误码分支，不解析错误消息。若存在 `error.details`，读取稳定的 `kind`、`subject`、`reason` 及可选 `source`、`received`、`expected`、`hint` 和 YAML 行列位置；不存在时不要从 prose 猜测。严格校验旧 v2 failure shape 的 consumer 需要允许这个可选字段；协议版本仍为 `2`。

可纠正的失败会直接在 `error.message` 说明已知选项、允许值或范围，以及配置修复目标。例如，非法的 `--mode` 会指出 `semantic` 和 `keyword`，但不回显被拒绝的原始值。默认 text 的 stderr 展示同一消息：

```text
error:
  code: usage.invalid
  message: --min-coverage-percent must be an integer from 0 through 100.
```

对应的 JSON 失败响应可在 `error.details` 携带同一组 validator-owned facts：

```json
{
  "ok": false,
  "error": {
    "code": "usage.invalid",
    "message": "--min-coverage-percent must be an integer from 0 through 100.",
    "details": [
      {
        "kind": "usage",
        "subject": "--min-coverage-percent",
        "reason": "out-of-range",
        "source": { "kind": "command-line" },
        "received": "101",
        "expected": { "kind": "integer-range", "min": 0, "max": 100 }
      }
    ]
  }
}
```

`message` 仍面向人；程序不得解析它。

协议仍为 version 2。未知失败使用安全的通用消息；程序应继续按 `error.code` 分支，不解析面向人的 message。

## 退出码

| 退出码 | 含义                                                              |
| ------ | ----------------------------------------------------------------- |
| `0`    | 成功结果，也可能只是接受了仍在执行的 operation。                  |
| `1`    | 命令特定的诊断或尚未完成的结果，例如 query 准备中或验证发现问题。 |
| `2`    | 调用失败，检查 `error.code`。                                     |

query 返回 `ok: true` 且 `data.state: "preparing"` 时退出码为 `1`，不代表查询结果为空。index 命令接受后台工作后可以退出 `0`；需要根据返回的 operation ID 继续检查是否完成。默认 text 也会完整展示相同状态和 ID；只有程序化 parser 需要使用 `--json`。

各命令参考说明其支持的状态和退出码。

## 本地 feedback 草稿

text 或 `--json` CLI 结果若指出了可复现的问题或有价值的改进，可以使用其 `diagnostics.traceId` 生成本地草稿：

```sh
lore feedback draft --trace-id <traceId> --kind bug
```

未传 `--output <directory>` 时，命令会在 `~/.lorelum/feedback/` 下创建唯一的 `report.json` 和 `report.md` 目录。默认会保留已留存的同 trace `error`、`warn`、`info` 调用链，以及普通 context、correlation ID 和已记录的 Error stack。它不会启动 Backend 或模型，也不会发网络请求、打开 URL、上传数据或创建 Issue。`--include-logs info` 与默认相同；`--include-logs debug` 只追加已经记录的 debug，若没有则报告 `debug-records-not-found`。

`--input <file|->` 是高级入口，适用于没有 trace 的人工观察或测试 fixture。草稿只是本机证据，不是提交；之后若决定把内容粘贴到公开 Issue，需要单独明确地执行该动作。删除 credential、secret 和其他不希望公开的信息即可，普通 query、结果、路径和 stack 不需要一概脱敏。
