The Lorelum Plugin adds engineering guidance and the `/lore` command to
WorkBuddy.

## Before you start

Complete [Quickstart](./quickstart). The `lore` command must be available to
WorkBuddy, and you need at least one installed Pack.

## Install

1. In WorkBuddy's plugin/marketplace management, add the Lorelum repository
   (`lorelum/lorelum` on GitHub) as a third-party marketplace, then install
   **Lorelum** from the `lorelum-plugins` marketplace.

2. Alternatively use the CodeBuddy CLI embedded in WorkBuddy to install
   straight from GitHub, without cloning the repository first:

   ```sh
   export WORKBUDDY_CONFIG_DIR=~/.workbuddy CODEBUDDY_CONFIG_DIR=~/.workbuddy
   codebuddy plugin marketplace add https://github.com/lorelum/lorelum
   codebuddy plugin install lorelum@lorelum-plugins
   ```

   Two caveats: running the CLI bare writes the standalone registry
   (`~/.codebuddy`), while the desktop client reads `~/.workbuddy`, so
   redirect the config directory first; and fully quit and restart WorkBuddy
   after installing, because a resident process only reloads the plugin
   registry on startup. For a local checkout (developer preview), replace the
   repository URL with the local repository-root path (the directory must
   contain `.codebuddy-plugin/marketplace.json`; the metadata directory or
   the manifest file path is rejected). `codebuddy` is the CLI bundled inside
   the WorkBuddy install (under `resources/app.asar.unpacked/cli/bin/codebuddy`
   on Windows); adjust the invocation path for your platform.

3. Start a new task. WorkBuddy receives the installed Pack Catalog at the
   session start.

## Use Lorelum

Check that `/lore` appears where WorkBuddy surfaces plugin commands. You can
run:

```text
/lore How should I verify this change?
```

Or ask WorkBuddy to use Lorelum before it finalizes an important decision.



WorkBuddy sessions also record read Practice candidates. When your agent
successfully runs `lore get` inside the session, the CLI reports the Practice
metadata to a running Backend, which stores it under
`~/.lorelum/sessions/workbuddy/<session id>/practice-reads.jsonl`. Reporting is
optional: it never starts the Backend and never changes the `lore get` result.

When WorkBuddy's Bash tool runs a command that mentions `lore`, the command is
prefixed with two `export` lines that carry the host and session identity —
this is how the read is associated with the conversation. The prefix does not
change the command's approval flow, arguments, or exit status, and it is not
added to non-shell tools. Which commands get the prefix follows the shared
[`agent.shellSessionInjection`](./configuration#agent-shell-session-identity)
setting. Subagents do not receive read-candidate hints on WorkBuddy: the host
dispatches a SubagentStart event but discards hook output, so no hint channel
exists there.

## Supported features

WorkBuddy provides the Skill, CLI query/get, Main Pack Catalog, and successful-read association. Manual and automatic compaction reuse the existing `SessionStart(source=compact)` to refresh Main's candidates before the task continues; startup/resume do not also deliver those hints.

The candidates are bounded historical metadata, not complete Practice bodies or adoption records. Reread a useful candidate with `lore get`. Empty candidates or an unavailable Backend preserve the Catalog and do not block continuation or start Backend for recovery.

Subagent candidate hints and a Plugin-provided subagent Catalog are absent; the discarded subagent Hook output is not a delivery path. See the [host capability table](./agent-setup#host-capabilities).


## Update

Open the plugin management surface, select Lorelum, and install the offered
update. For a local checkout, uninstall and reinstall it from your marketplace
after you change Plugin files.

## Troubleshoot

If `/lore` or guidance is missing:

1. Confirm Lorelum is installed and enabled in the plugin management surface.
2. Confirm `lore --version` works in the environment used by WorkBuddy.
3. Start a new task after installing or updating.

For retrieval or model problems, see [Troubleshooting](./troubleshooting).
