The Lorelum Plugin makes engineering guidance available in Codex when it can help with the task at hand.

## Before you start

Complete [Quickstart](./quickstart). The `lore` command must be available to Codex, and you need at least one installed Pack.

## Install

```sh
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

Approve the Plugin's Hook if Codex asks, then start a new task.

### Moving from an earlier alpha

If you previously installed `lorelum@lorelum`, remove it and the old marketplace source before installing the current Plugin:

```sh
codex plugin remove lorelum@lorelum
codex plugin marketplace remove lorelum
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

## Use Lorelum

In a new task, ask Codex to use Lorelum before it settles an important plan or implementation decision. For example:

```text
Use Lorelum to find guidance for this change before you finalize the plan.
```

After updating both the Plugin and CLI to versions containing this feature, a successful `lore get` inside a shell tool can leave a short candidate hint for the conversation, including when a script or pipeline runs it. Non-shell tools are skipped. When a subagent starts, it may see candidate IDs, titles, and applicability hints, then decide whether to read a Practice itself. The hint is not the Practice body or evidence that the parent adopted it. The Hook does not automatically run a query or `get`, and it does not restore these hints to the main agent after compaction yet.

The existing local Backend stores the optional list at `~/.lorelum/sessions/<host>/<session-id>/practice-reads.jsonl`. The folder uses the host's session ID directly and can hold other session data separately in the future. Deleting a worktree or restarting the Backend does not remove recorded hints. The Backend must already be running and reachable when the Hook opens a shell-tool window and when `get` reports its read. Neither operation starts it merely to record hints. If it is unavailable, or a read falls outside an active window, that hint may be missed without changing the `get` result. Window-based association can miss or misattribute a read when conversations use the same directory simultaneously. Check relevance with `lore get <practice-id>` before using a hint; do not treat the list as a task record or access-control boundary.

## Update

```sh
codex plugin marketplace upgrade lorelum-plugins
codex plugin add lorelum@lorelum-plugins
```

Approve changed Hooks if Codex asks, then start a new task.

## Troubleshoot

If Codex does not appear to use Lorelum:

1. Confirm the Plugin is installed and enabled.
2. Confirm `lore --version` works for the Codex environment.
3. Re-approve the Hook if Codex shows it needs review.
4. Start a new task after any installation or update.

For retrieval or model problems, see [Troubleshooting](./troubleshooting).
