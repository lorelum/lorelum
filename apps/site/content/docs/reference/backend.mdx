---
title: Backend commands
description: Start, inspect, and stop Lorelum's local service.
---

The Backend is the long-lived local host for embedding and semantic index operations. Start, status, and stop are independent of Store selection.

```sh
lore backend start
lore backend status
lore backend stop
# Agent-only safe handoff
lore backend stop --if-idle
```

`start` initializes missing default configuration, starts or reuses a compatible local instance, and waits until it is ready. It does not load the model. `status` reports `state`, `model`, and, when available, `instanceId` and `buildIdentity`; it never starts a process. Explicit `stop` waits for the service to exit and is safe when it is already stopped.

After an upgrade, the current CLI can explicitly stop a verified local Backend from another build. With a compatible protocol it uses authenticated shutdown; with an incompatible protocol it uses the private runtime record plus exact process identity to terminate only that owned lifecycle after a graceful deadline. It never requires the old CLI to still be installed, and never stops an arbitrary process that happens to use the local port.

`stop --if-idle` rechecks private activity and task leases under the lifecycle lock and stops only a proven idle Backend. Model preparation, semantic indexing, a valid lease, or unknown activity returns `deferred` without interrupting the other task. Follow the complete error message: run `lore backend stop --if-idle`; only after `state: "stopped"`, run `lore backend start`, then retry the original command with the same arguments. If stop returns `deferred`, leave the instance and task running, report the safe refusal, and do not retry in the background or use ordinary stop without explicit user consent.

The default service address is loopback (`127.0.0.1:26186`). Global `--store-root` affects Store data only. `--log-level` controls stderr progress and diagnostics.

Backend errors include `backend.unavailable`, `backend.port-conflict`, `backend.build-mismatch`, `backend.protocol-mismatch`, `backend.incompatible`, `backend.config-invalid`, `backend.busy`, `backend.failed`, and `backend.deadline-exceeded`. Build/protocol mismatch across query/model/index/backend commands uses a complete actionable message, not a policy object; unavailable instructs `lore backend start` and retry. Ownership, listener, and authentication problems retain specific corrective guidance. Query and status reads never stop a process because of mismatch. Success exits `0`; failures exit `2`. Use `lore describe backend.start` (or the other subcommand) for the installed schema.
