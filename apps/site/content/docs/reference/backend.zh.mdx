---
title: Backend 命令
description: 启动、查看和停止 Lorelum 本地服务。
---

Backend 是承载 embedding 和 semantic index 操作的长期本地服务。start、status、stop 与 Store 选择相互独立。

```sh
lore backend start
lore backend status
lore backend stop
# 仅供 Agent 自动恢复使用
lore backend stop --if-idle
```

`start` 会初始化缺失的默认配置，启动或复用兼容的本地实例，并等待其 ready；不会加载模型。`status` 返回 `state`、`model`，以及可用时的 `instanceId`、`buildIdentity`，不会启动进程。显式 `stop` 等待服务退出，服务已停止时重复调用也安全。

升级后，当前 CLI 可以显式停止另一 build 的、已经验证为同一实例的本地 Backend。protocol 兼容时走 authenticated shutdown；protocol 不兼容时，当前 CLI 使用私有 runtime record 与精确进程身份，在 graceful deadline 后只终止同一 owned lifecycle。它不要求旧 CLI 仍存在，也不会因为某个进程占用了本地端口就终止它。

`stop --if-idle` 在 lifecycle lock 内重新检查私有 activity 与 task lease，仅停止可证明 idle 的 Backend。模型准备、semantic indexing、有效 lease 或未知 activity 返回 `deferred`，不打断另一任务。按完整错误消息执行 `lore backend stop --if-idle`；只有返回 `state: "stopped"` 才运行 `lore backend start`，启动成功后以相同参数重试原命令。若 stop 返回 `deferred`，保留实例与任务，说明安全拒绝，不后台重试，也不在未经用户明确同意时使用普通 stop。

默认服务地址为 loopback（`127.0.0.1:26186`）。全局 `--store-root` 只影响 Store 数据；`--log-level` 控制 stderr 的进度与诊断日志。

常见错误包括 `backend.unavailable`、`backend.port-conflict`、`backend.build-mismatch`、`backend.protocol-mismatch`、`backend.incompatible`、`backend.config-invalid`、`backend.busy`、`backend.failed` 和 `backend.deadline-exceeded`。跨 query/model/index/backend 的 build/protocol mismatch 使用完整 message 指导安全恢复，不携带策略对象；unavailable 指示 `lore backend start` 后重试。ownership、listener 与认证问题返回具体修正方向。query 和状态读取不会因 mismatch 自动停止进程。成功退出 `0`，失败退出 `2`。各子命令 schema 见 `lore describe backend.start` 等。
