## 安装

```sh
lore pack install agentic-coding
```

全局 `--store-root <path>` 选择 LocalStore，`--log-level <level>` 控制 stderr 日志；`--registry <source>` 与 `--path <directory>` 仅用于 install 和 update，并选择互斥的 source route。

指定版本可固定发行内容。省略版本时，使用选中 Registry 的最新版本。不传 `--registry` 时，Lorelum
使用保存的 default Registry；没有 default 时使用内置 `official`。`--registry` 可以接已保存 alias，
也可以接一次性的受支持 Git locator。catalog 命令、transport 和“不回退”行为见[安装与管理 Pack](../packs)。

```sh
lore pack install team-pack --registry team
lore pack update team-pack@0.2.0 --registry https://gitlab.com/acme/team-packs.git
```

如果要从一次性的本地 Pack 目录读取，则不要传 Pack positional，改用 `--path`：

```sh
lore pack install --path ./packs/team-pack
lore pack update --path ../team-pack
```

目录路径相对于命令执行时的 cwd 解析，必须是可读取的 Pack root；它不要求 Git 或
`.lorelum/registry.yaml`，不会保存、watch，也不会写入 Store provenance。`--path` 不能与 Pack
specifier 或 `--registry` 混用。

重复安装相同内容是安全的。如果同名 Pack 已安装不同内容，会返回 `pack.update-required`，请改用 `pack update`。

安装也会启动 Pack 所需的 semantic index 工作。结果还会返回可直接读取的公开 `packRoot`，路径为 `packs/p-<pack-name>/current`；`indexSync` 为 `ready`、`pending` 或 `failed`，index 失败不会撤销 Pack 安装。Registry、source、Pack 校验、Store 与 `pack.update-required` 错误退出 `2`，恢复步骤见[故障排查](../troubleshooting)。

Registry source 的结果包含 `registry` 和 `source: { type: "git" | "local-git", ref, commit }`；
目录 source 的结果包含 `source: { type: "directory" }`，不包含 Registry、Git ref/commit 或输入
路径。`pack install --path` 与其他 install 一样有 `indexSync`；`pack update --path` 保持现有
update 结果，不会启动 index synchronization。

本地目录无法打开时返回 `source.unavailable`；目录可打开但 Pack 解码或校验失败时返回
`pack.invalid`。这些错误不会泄露 source path，也不会替换已安装 Pack。选中的 Registry 不可用时
同样会直接失败，不会尝试其他保存 source，也不会静默切回 `official`。

## 浏览

```sh
lore pack list
lore pack list --details
lore pack list agentic-coding
```

`lore pack list` 的默认 text 显示 Pack 名称和版本。`--details` 继续用于查看富元数据，会显示已声明的描述和非空适用范围；它不是通用展开选项。使用 `--verbose` 可将完整结果 data 输出为 text，使用 `--json` 可获得完整 envelope 和 data；即使同时传入 `--verbose`，JSON 也不变。指定 Pack 名则列出其中的 Practice，并在 `pack` object 上返回 `packRoot`。把结果中的 ID 传给 [get](./get)。Practice 摘要刻意不重复每条 Practice 或资源路径。

明确浏览某个 Pack 时，`lore pack list <name>` 会在默认 text 中显示当前 `packRoot` 和其中的 Practice 摘要。普通 query 后读取 Practice 时，使用 [get](./get) 返回的对应 Store source `packRoot`；每个 source 都有自己的 locator。SessionStart Pack Catalog 提供名称、描述和适用范围，但不包含 Pack root，也不会自动加载或枚举资源。

Store 的 `packRoot` 是可变的 `current` view，不是 artifact digest 路径：发生 mutation 后，相同路径可能解析到新 bytes，或在 Pack 移除后消失。重新运行 `lore get`，或用 `lore pack list <name>` 明确浏览后，再将它视为当前 root；不能从 Pack 名或 Store 布局推导路径。详见 [Pack 格式](./pack-format)。

## 更新和移除

```sh
lore pack update <pack-name>@<version>
lore pack remove <pack-name>
```

每次更新一个 Pack。两条命令在 Pack 未安装时返回 `pack.not-installed`。

## Validate a Pack

```sh
lore validate /path/to/pack
```

校验检查 Pack 并报告本地化状态，也会报告非法资源目录和 `resource:` target，但不会执行 Pack script。适合[创建 Pack](../create-pack)时使用；完整资源边界见 [Pack 格式](./pack-format)。退出码为 `0`、`1` 或 `2`；具体诊断与命令错误的区别见结果和 `lore describe validate`。

## 选择 Store

```sh
lore --store-root /path/to/store pack install agentic-coding
```

所有 Pack 操作都使用选中的 Store。完整命令 schema 与错误见 `lore describe`。
