## 安装

```sh
lore pack install agentic-coding
```

全局 `--store-root <path>` 选择 LocalStore，`--log-level <level>` 控制 stderr 日志；`--registry <locator>` 仅用于 install 和 update。

指定版本可固定发行内容。省略版本时，使用 Registry 选择的最新版本。其他 Registry 通过 `--registry owner/repository` 指定；私有 Registry 请使用 SSH locator（`git@github.com:owner/repo.git`），见[安装与管理 Pack](../packs)。

重复安装相同内容是安全的。如果同名 Pack 已安装不同内容，会返回 `pack.update-required`，请改用 `pack update`。

安装也会启动 Pack 所需的 semantic index 工作。结果还会返回可直接读取的公开 `packRoot`，路径为 `packs/p-<pack-name>/current`；`indexSync` 为 `ready`、`pending` 或 `failed`，index 失败不会撤销 Pack 安装。Registry、source、Pack 校验、Store 与 `pack.update-required` 错误退出 `2`，恢复步骤见[故障排查](../troubleshooting)。

## 浏览

```sh
lore pack list
lore pack list --details
lore pack list agentic-coding
```

第一条列出已安装 Pack，并在每个 Pack 上返回当前本机 `packRoot`；`--details` 加上发现所需的元数据，也会返回 Pack locator。指定 Pack 名则列出其中的 Practice，并在 `pack` object 上返回 `packRoot`。把结果中的 ID 传给 [get](./get)。Practice 摘要刻意不重复每条 Practice 或资源路径。

`packRoot` 适合调用方已经明确选择一个 Pack 后进行浏览或维护；它不会进入 query 结果，但 Codex 和 ZCode Plugin 注入的 Pack Catalog 会为每个已安装 Pack 提供它。Catalog 仍不会自动加载或枚举 Pack 资源。它是可变的 `current` view，不是 artifact digest 路径：发生 mutation 后，相同路径可能解析到新 bytes，或在 Pack 移除后消失。重新运行 `pack list` 或 `get` 后再将它视为当前 root，不能从 Pack 名或 Store 布局推导路径。详见 [Pack 格式](./pack-format)。

## 更新和移除

```sh
lore pack update <pack-name>@<version>
lore pack remove <pack-name>
```

每次更新一个 Pack。两条命令在 Pack 未安装时返回 `pack.not-installed`。

## Validate a Pack

```sh
lore validate /path/to/pack
```

校验检查 Pack 并报告本地化状态，也会报告非法资源目录和 `resource:` target，但不会执行 Pack script。适合[创建 Pack](../create-pack)时使用；完整资源边界见 [Pack 格式](./pack-format)。退出码为 `0`、`1` 或 `2`；具体诊断与命令错误的区别见结果和 `lore describe validate`。

## 选择 Store

```sh
lore --store-root /path/to/store pack install agentic-coding
```

所有 Pack 操作都使用选中的 Store。完整命令 schema 与错误见 `lore describe`。
