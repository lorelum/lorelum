## Install

```sh
lore pack install agentic-coding
```

Global `--store-root <path>` selects the LocalStore and `--log-level <level>` controls stderr logs. `--registry <source>` and `--path <directory>` are specific to install and update; they select mutually exclusive source routes.

A version pins the release. Omitting it selects the selected Registry's latest release. Without `--registry`, Lorelum uses the saved default Registry or the built-in `official` source. Pass a saved alias or a one-time supported Git locator with `--registry`; see [Install and manage Packs](../packs) for catalog commands, accepted transports, and no-fallback behavior.

```sh
lore pack install team-pack --registry team
lore pack update team-pack@0.2.0 --registry https://gitlab.com/acme/team-packs.git
```

For a transient local Pack directory, omit the Pack positional and use `--path`:

```sh
lore pack install --path ./packs/team-pack
lore pack update --path ../team-pack
```

The directory path is resolved relative to the command's current working directory. It must be a
readable Pack root; it does not need Git or `.lorelum/registry.yaml`, and it is not saved, watched, or
written into Store provenance. `--path` cannot be combined with a Pack specifier or `--registry`.

Installing the same artifact again is safe. If the installed name has different content, Lorelum returns `pack.update-required`; use `pack update`.

Installation also starts the semantic index work needed for the Pack. The result includes its readable public `packRoot` at `packs/p-<pack-name>/current`; `indexSync` reports `ready`, `pending`, or `failed`, and an index failure leaves the Pack installed. Registry, source, Pack validation, Store, and `pack.update-required` errors exit `2`; see [Troubleshooting](../troubleshooting).

Registry-backed results include `registry` and `source: { type: "git" | "local-git", ref, commit }`.
Directory-backed results include `source: { type: "directory" }` and omit Registry, Git ref/commit,
and the input path. `pack install --path` has the same `indexSync` field as other installs;
`pack update --path` keeps the existing update result and does not start index synchronization.

If a local directory cannot be opened, the command returns `source.unavailable`; if it opens but fails
Pack decoding or validation, it returns `pack.invalid`. These errors do not expose the source path and
do not replace an already installed Pack. A selected Registry source that is unavailable also fails
without trying another saved source or silently switching back to `official`.

## Browse

```sh
lore pack list
lore pack list --details
lore pack list agentic-coding
```

`lore pack list` default text shows Pack names and versions. `--details` keeps its rich-metadata role and shows declared descriptions and non-empty applicable scopes; it is not a general expansion flag. Use `--verbose` to render the complete result data as text, or `--json` to receive the complete envelope and data. JSON is unchanged when `--verbose` is also present. A Pack name lists that Pack's Practices and returns its `packRoot` on the `pack` object. Use a returned ID with [get](./get). Practice summaries deliberately do not repeat per-Practice paths or resource paths.

When explicitly browsing a Pack, `lore pack list <name>` shows its current `packRoot` in default text alongside its Practice summaries. For ordinary query-and-read workflows, use the `packRoot` on the relevant Store source returned by [get](./get); each source has its own locator. The SessionStart Pack Catalog contains names, descriptions, and applicable scopes, but no Pack roots, and does not load or enumerate resources automatically.

A Store `packRoot` is a mutable `current` view, not an artifact digest path: after a mutation the same path may resolve to newer bytes or disappear after removal. Rerun `lore get` or explicitly browse with `lore pack list <name>` before treating it as current, rather than deriving a root from a Pack name or Store layout. See [Pack format](./pack-format).

## Update and remove

```sh
lore pack update <pack-name>@<version>
lore pack remove <pack-name>
```

Update one Pack at a time. Both commands return `pack.not-installed` if the Pack is absent.

## Validate a Pack

```sh
lore validate /path/to/pack
```

Validation checks the Pack and reports localization state. It also reports invalid resource directories and `resource:` targets, but never executes Pack scripts. Use it while [creating a Pack](../create-pack) and read [Pack format](./pack-format) for the complete resource boundary. Exit codes are `0`, `1`, or `2`; inspect the result and `lore describe validate` for the distinction between diagnostics and command errors.

## Choose the Store

```sh
lore --store-root /path/to/store pack install agentic-coding
```

All Pack operations use the selected Store. Command schemas and errors are available through `lore describe`.
