## Install

```sh
lore pack install agentic-coding
```

Global `--store-root <path>` selects the LocalStore and `--log-level <level>` controls stderr logs. `--registry <locator>` is specific to install and update.

A version pins the release. Omitting it selects the Registry's latest release. For a different Registry, pass `--registry owner/repository`; for a private Registry, pass an SSH locator (`git@github.com:owner/repo.git`) — see [Install and manage Packs](../packs).

Installing the same artifact again is safe. If the installed name has different content, Lorelum returns `pack.update-required`; use `pack update`.

Installation also starts the semantic index work needed for the Pack. The result includes its readable public `packRoot` at `packs/p-<pack-name>/current`; `indexSync` reports `ready`, `pending`, or `failed`, and an index failure leaves the Pack installed. Registry, source, Pack validation, Store, and `pack.update-required` errors exit `2`; see [Troubleshooting](../troubleshooting).

## Browse

```sh
lore pack list
lore pack list --details
lore pack list agentic-coding
```

The first command lists installed Packs and returns each Pack's current local `packRoot`; `--details` adds metadata for discovery and also returns the Pack locator. A Pack name lists that Pack's Practices and returns its `packRoot` on the `pack` object. Use a returned ID with [get](./get). Practice summaries deliberately do not repeat per-Practice paths or resource paths.

`packRoot` is useful when the caller explicitly chose a Pack to browse or maintain. It is not injected into query results, but the Pack Catalog injected by the Codex and ZCode Plugins includes it for every installed Pack. The Catalog still does not load or enumerate Pack resources automatically. It is a mutable `current` view, not an artifact digest path: after a mutation the same path may resolve to newer bytes or disappear after removal. Rerun `pack list` or `get` before treating it as current, rather than deriving a root from a Pack name or Store layout. See [Pack format](./pack-format).

## Update and remove

```sh
lore pack update <pack-name>@<version>
lore pack remove <pack-name>
```

Update one Pack at a time. Both commands return `pack.not-installed` if the Pack is absent.

## Validate a Pack

```sh
lore validate /path/to/pack
```

Validation checks the Pack and reports localization state. It also reports invalid resource directories and `resource:` targets, but never executes Pack scripts. Use it while [creating a Pack](../create-pack) and read [Pack format](./pack-format) for the complete resource boundary. Exit codes are `0`, `1`, or `2`; inspect the result and `lore describe validate` for the distinction between diagnostics and command errors.

## Choose the Store

```sh
lore --store-root /path/to/store pack install agentic-coding
```

All Pack operations use the selected Store. Command schemas and errors are available through `lore describe`.
