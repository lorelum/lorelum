本页是供能够执行本地命令的 Agent 使用的技术参考，也适合需要把这些说明直接交给 Agent 的高级用户。普通安装和第一次使用请从[接入 Agent](./agent-setup)开始。可以直接向 Agent 提供本页的 [Markdown 版本](./agents.md)。

## 配置环境

在命令环境中检查 `lore --version`。若不可用，按[安装](./installation)准备 CLI，并保留完整发行目录。

请按 Agent 实际运行命令的宿主选择安装器。macOS Apple Silicon 和 Linux x64 使用 Unix 安装器：

```sh
curl -fsSL https://raw.githubusercontent.com/lorelum/lorelum/main/install.sh | sh -s -- --version 0.1.0-alpha.2
```

Windows x64 使用 PowerShell：

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/lorelum/lorelum/main/install.ps1))) -Version 0.1.0-alpha.2
```

Windows 不要运行 `install.sh`，也不要双击安装脚本。请在已经打开的 PowerShell 会话中运行上面的命令，保留错误输出。macOS 是优先适配、验证更充分的发布平台；Linux 和 Windows 为尽力支持。在将其他环境视为兼容前，请先阅读[安装](./installation)说明。

检查已安装 CLI 和 Pack：

```sh
lore describe
lore pack list --details
```

用户需要的 Pack 缺失时安装它。官方工程 Pack 的安装命令是：

```sh
lore pack install agentic-coding
```

按[接入 Agent](./agent-setup)配置当前宿主。Codex 和 ZCode 分别使用各自的[官方 Plugin](./agent-setup)。围绕当前仓库执行一次查询并读取完整 Practice，验证配置。

若使用自定义 `--store-root`，install、query、get 和 index 命令应保持一致。它选择 Pack 和索引数据，不选择其他模型或 Backend。

## 在需要工程判断时检索

适合检索的时刻包括确定范围、划分实现边界、选择验证、恢复上下文，以及准备宣布完成。

说明具体任务和当前时刻：

```sh
lore query "我正在实现账户设置，局部组件测试已通过，准备判断整个功能是否已经完成。"
```

不要将 Pack 目录当作完整指导，也不要假定它穷尽所有相关知识。查询应服务于当前判断，无需在每条命令前机械检索。

## 读取并应用

根据结果中的 `title` 和 `appliesWhen` 选择候选，然后读取全文：

```sh
lore get <practice-id>
```

使用 query 或 Pack 列表返回的精确 `practiceId`。结合当前代码和用户要求检查适用条件。Practice 辅助工程判断，不会授权新增任务范围，也不能替代完成证据。

新事实改变判断时，再次检索。说明相关指导如何影响工作，不要声称应用了未读取或不相关的 Practice。

### 按需使用链接的 Pack 资源

Practice 可以通过 `resource:` target 链接 Pack 内材料，例如 `resource:references/api-compatibility.md`。从 `get` 结果中相同 source 的 `packRoot` 解析它。只有当前判断需要额外细节时才读取 reference；asset 先复制到任务工作区再编辑；script 仅在当前任务授权、且 Practice 已说明用途和输入时运行。

link 是默认任务路由，不是文件访问 allowlist。Codex 或 ZCode Plugin 在 SessionStart 注入的 Catalog 会为每个已安装 Pack 提供可直接读取的当前 `packRoot`，当 Pack 上下文已经明确时可以直接使用它。对于已经取回的 Practice，多个 source 必须保持分开，并使用相同 source 的 `get` root，而不能静默挑选 Catalog entry。root 是可变的 current view：发生 Pack mutation 后，重新执行 `get` 或 `pack list` 后再将它视为当前 source；不要通过 Store 内部实现推导 root。不要假定 Pack script 会在 install、validate、query、list、get、index 或 recovery 期间运行。

## 阅读默认输出与排查问题

Agent 的正常调用使用默认 text 并直接阅读。它包含与 JSON 相同的公开业务数据，包括 ID、source、状态、进度、diagnostic 和 metadata，不是摘要；但不得将其排版当作可解析协议。结果异常、需要排查，或需要核对精确 protocol 字段时，再用 `--json` 重跑同一命令：stdout 此时是单行 JSON envelope，stderr 仍承载诊断和进度。会以程序方式解析输出的脚本和 CI 必须使用 `--json`。

| 结果 | 后续动作 |
| --- | --- |
| query 可用，显示 Practice | 选择相关结果，用 `get` 读取。 |
| 显示 `state: preparing`、退出码 `1` | 检查模型状态，用 `lore model load` 等待，再重试原查询。 |
| query 可用，但显示空结果列表 | 检查已安装 Pack，必要时补充更具体的任务描述。 |
| index operation 已被接受 | 根据可见的 operation ID 检查，直到完成或失败。 |
| 命令失败、退出码 `2` | 阅读 code/recovery，按[故障排查](./troubleshooting)处理；只有需要 protocol 级排查时才用 `--json`。 |

默认使用 semantic query。语义查询失败不代表没有相关指导。仅在明确需要离线查询或隔离语义运行时问题时使用 keyword 模式，并明确说明检索模式。

## 在排查时检查已安装合同

```sh
lore describe query --json
lore describe get --json
lore describe pack.list --json
lore describe index.build --json
```

只有排查 protocol 或 automation 问题时才用这些 JSON schema 查询参数、字段、错误和退出码。普通检索继续使用默认 text。更多内容见 [CLI 参考](./cli)和[文档概述](./index.md)。
