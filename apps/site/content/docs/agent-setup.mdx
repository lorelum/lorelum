## Host capabilities

All official Plugins use the same Lorelum Skill, `lore query`, and `lore get`. Compare the individual features below; a Plugin installation does not imply that every host lifecycle feature is available.

Cursor's Catalog arrives asynchronously and can miss the first turn; the Skill lists installed Packs once when it is absent. omp's child Catalog is opt-in with `agent.subagentPackCatalog: true`, independently of read hints. Its nested task/eval children retain the originating Main's candidates, while their own reads stay in their own sessions.

Read association requires a successful `get`, an already-running Backend, and a usable session identity. The shared [shell setting](./configuration#agent-shell-session-identity) selects eligible commands; a missed record does not change `get`. Hints contain bounded historical metadata, never full Practice bodies or proof of adoption. Main compact recovery uses only the existing compact event, not an extra startup/resume delivery. See each host's guide for the available entry points and recovery behavior.

## Other agents

Agents that can execute commands can use the same CLI. Install the Skill through the host's supported mechanism. If the host uses project instructions instead, include the Skill's retrieval instructions there.

The essential behavior is to describe the task and current decision with `lore query`, read relevant results with `lore get`, and apply the guidance within its stated conditions. The Agent reads default text directly; it does not parse its layout. When a retrieved Practice contains a `resource:` link, the installed Skill explains how to resolve it from the displayed mutable current `packRoot`, read references on demand, copy assets before editing, and explicitly run a script only under task authorization. Use `--json` only to diagnose an unexpected result or inspect protocol details. See [Agent instructions](./agents) for the full execution contract.

## First use

Start a new task and tell your agent:

```text
Use Lorelum to find engineering guidance for this task before you finalize the plan.
```

The agent should use the installed guidance when it can help with a design, implementation, verification, or recovery decision.

## Session read hints

Lorelum can keep a short list of Practices read during an agent conversation. A successful `lore get` reports a candidate only when the local Backend is already running and the host integration can associate the read with a session. A host may pass its session identity to the command or use a supported activity-window fallback. The Backend keeps the list under `~/.lorelum/sessions/<host>/<session-id>/practice-reads.jsonl`; it survives a Backend restart or deletion of the original worktree. A failed or unassociated read is simply not added, and the result of `get` does not change.

An integration with a supported child-context entry can pass those candidates to a new subagent as IDs, titles, and applicability hints. omp supplies them in task/eval model requests; Codex and Claude Code use their subagent-start Hooks. The subagent decides whether to run `lore get` itself; no Practice body is injected automatically. The list may be incomplete and says only that a Practice was read, not that the parent adopted it. It is not a task log or an access-control record. Each host Plugin defines its supported integration.

Claude Code, Codex, WorkBuddy, and omp also refresh Main's candidates after compaction. The agent rereads a candidate only when it is useful to the current task. Missing candidates or an unavailable Backend do not block continuation or start the Backend merely to restore hints. Cursor and ZCode have no post-compact refresh entry; normal query/get remains available.

For hosts that can pass session identity to shell commands, the shared [Agent setting](./configuration#agent-shell-session-identity) controls which commands receive it. See each host's guide for its Hook behavior.

## If it does not work

1. Check that `lore --version` works in the environment used by the agent.
2. Check that the Skill or Plugin is installed and enabled.
3. Start a new task after installing or updating a Plugin.
4. Use [Troubleshooting](./troubleshooting) if Lorelum starts but cannot retrieve guidance.

## Update

For a file-based Skill, replace `SKILL.md` with the latest version. Update Plugins through the host's Plugin mechanism; each installation page explains the steps.
