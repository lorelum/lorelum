Lorelum runs with defaults. User-level settings live in `~/.lorelum/config.yaml` and apply to every Store.

## Agent shell session identity

The shared `agent.shellSessionInjection` setting controls when an Agent integration that supports shell session binding passes a conversation identity to its shell commands. The default, `lore-only`, checks whether the outer command text contains `lore` as a separate word. Direct calls, pipelines, and command substitutions containing `lore` match; the Hook does not parse the command or read script files. For example, `sh script.sh` does not match even if that script calls `lore get`, so the read may not be associated with the conversation. Merely mentioning `lore` in the outer text may match without executing it.

To cover indirect calls inside local scripts, add this to `~/.lorelum/config.yaml`:

```yaml
agent:
  shellSessionInjection: all-shell
```

`all-shell` passes the identity to every supported shell tool command, not to non-shell tools. Remove the field or set it to `lore-only` to restore the default. Supporting Hooks read changes on their next invocation; a Backend restart is not needed. Invalid configuration leaves that Hook call unchanged and does not block the tool. Both modes still run the Hook on each matched shell call; the default reduces command rewriting and variable visibility, not Hook process overhead.

This is a shared setting for agent integrations, not a Codex-specific one. It only affects a host whose Plugin supports shell session binding; setting the field alone does not add a Hook. See [Agent integration](./agent-setup#session-read-hints) for the shared read-hint behavior and each host's guide for its supported Hooks.

## Store scope

Use one `--store-root` consistently for Pack installation, index operations, query, and get:

```sh
lore --store-root /path/to/store pack install agentic-coding
lore --store-root /path/to/store query "how should I verify an authentication change?"
```

This option selects Pack data in the Store. It does not select the query cache, model, model cache, Backend address, or runtime directory.

## Query cache and wait policy

Derived query data is user-level and rebuildable. Its default root is `~/.lorelum/cache`; it never writes project `.lorelum/`, Git metadata, or LocalStore. Use `--cache-root <path>` to isolate one query, index, or cache command. Equivalent final Practice corpora reuse artifacts and embedding vectors regardless of directory, Git/worktree, branch, commit, or mtime.

```yaml
query:
  maxWaitMs: 3000
  minCoveragePercent: 0
```

These are integer milliseconds from 0 through 120000 and an integer percentage from 0 through 100. A query timeout leaves its accepted operation running; verified current progress that meets the percentage may return a partial result. Use `lore cache status` to inspect cache state and `lore cache prune` to remove unused derived state explicitly.

## Model and Backend

Semantic query and semantic index operations use the fixed local embedding model. The default cache is `~/.lorelum/models/`.

```sh
lore backend start
lore model status
lore model load
lore model unload
lore backend status
lore backend stop
lore backend start
```

Semantic commands start Backend when needed. Standalone model commands require it to be running, so start it explicitly when preparing the model in advance. `model load` waits for preparation and loading; `unload` releases the runtime but keeps the cache. Restart Backend after changing model or Backend settings; Agent Hook settings take effect on the next Hook call.

## Embedding settings

```yaml
embedding:
  threads: 4
  download:
    enabled: true
    connectTimeoutSeconds: 30
    stallTimeoutSeconds: 60
    maxAttempts: 3
```

| Field | Default | Contract |
| --- | --- | --- |
| `embedding.modelPath` | unset | Absolute path to the fixed model; validated, never overwritten. |
| `embedding.cacheDirectory` | `~/.lorelum/models` | Absolute cache path when `modelPath` is unset. |
| `embedding.threads` | `4` | Integer from 1 to 64. |
| `embedding.download.enabled` | `true` | Whether missing model files may be downloaded. |
| `embedding.download.url` | built-in pinned source | HTTPS mirror for the same file; resumable downloads required. |
| `embedding.download.connectTimeoutSeconds` | `30` | Connection timeout in seconds. |
| `embedding.download.stallTimeoutSeconds` | `60` | Maximum time without received bytes. |
| `embedding.download.maxAttempts` | `3` | Attempts for transient failures. |

Custom paths or mirrors must provide the fixed Q4_0 file (66,345,216 bytes; SHA-256 `18e8ce8ce834790618e90d26bed465cca87362076f3042eb0d8eee0732596f59`). A different model is rejected. With downloads disabled and no valid file, loading reports `embedding.not-configured`.

## Backend timeouts

```yaml
backend:
  startupTimeoutMs: 10000
  requestTimeoutMs: 5000
  shutdownTimeoutMs: 5000
```

Each value is an integer from 1 to 120000 milliseconds. `LORELUM_BACKEND_STARTUP_TIMEOUT_MS`, `LORELUM_BACKEND_REQUEST_TIMEOUT_MS`, and `LORELUM_BACKEND_SHUTDOWN_TIMEOUT_MS` override YAML. Startup covers service and native runtime; request covers one request; shutdown covers unload and stop.

Model-file download time is controlled by the embedding download settings above, not the native-runtime startup budget. Backend reads these settings once when it starts, so changing YAML or environment variables does not change an already-running instance; restart Backend to apply them. `backend status`, `backend stop`, and model commands never write your configuration file.
