Lorelum Plugin 会在当前任务需要工程判断时，让 Codex 使用相关的工程指导。

## 开始前

请先完成[快速开始](./quickstart)。运行 Codex 的环境需要能使用 `lore` 命令，并且至少安装了一个 Pack。

## 安装

```sh
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 要求审阅 Hook，请确认后再启动一个新任务。

### 从早期 alpha 迁移

如果此前安装过 `lorelum@lorelum`，请先移除旧 Plugin 和旧 marketplace source，再安装当前版本：

```sh
codex plugin remove lorelum@lorelum
codex plugin marketplace remove lorelum
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

## 使用 Lorelum

在新任务中，要求 Codex 在确定重要的计划或实现决定前使用 Lorelum。例如：

```text
请在确定这个改动的计划前，用 Lorelum 查找相关指导。
```

在 Codex 的 shell tool 中成功执行 `lore get`，且命令继承了会话身份后，Lorelum 会为当前对话记录一条简短的候选提示。启动子 Agent 时，它可能看到候选 ID、标题和适用条件，再自行决定是否读取。提示不是 Practice 正文，也不代表主 Agent 已采纳它；Hook 不自动 query 或 `get`，目前也不会在主 Agent compact 后恢复这些提示。

这份可选列表由现有本机 Backend 管理，存放在 `~/.lorelum/sessions/<宿主>/<会话 ID>/practice-reads.jsonl`；目录直接使用宿主的会话 ID，将来也可以分别存放其他会话数据。删除 worktree 或重启 Backend 不会清掉已记录的候选。成功的 `get` 只向已经运行的 Backend 报告；Hook 不会在每条 shell 命令前连接 Backend。Hook 未获信任或命令主动清空环境时，可能漏记；这不影响 `get` 的结果。使用提示前仍应通过 `lore get <practice-id>` 核对是否适用，不要把候选列表当成任务记录或权限依据。

### 控制哪些命令注入会话身份

默认 `lore-only`：只有 Codex 提交的 shell 命令文本含独立的 `lore` 字样时，Hook 才会注入会话变量。直接执行 `lore get`、管道或命令替换中的 `lore` 都能匹配；`sh script.sh` 等外层命令没有 `lore` 时，即使脚本内部执行了 `lore get`，也不会记录到当前会话。Hook 不读取脚本文件，也不解析命令是否真的运行了 `lore`，所以文本里只是提到它时也可能注入。

如果需要覆盖脚本内部间接调用，在用户级 `~/.lorelum/config.yaml` 加入这个 Agent 共用配置：

```yaml
agent:
  shellSessionInjection: all-shell
```

`agent.shellSessionInjection` 是 Agent 共用配置，不属于 Codex 专用段。目前只有 Codex 集成会改写 shell 命令，给其他 Agent 安装 Plugin 不会仅凭这项配置就启用注入。在 Codex 中，`all-shell` 会在每个 shell tool 命令前注入；非 shell tool 在两种模式下都不会注入。删去该字段或设为 `lore-only` 即恢复默认。修改配置后，下次 Hook 调用就会读取新值，无需重启 Backend。两种模式下 Hook 仍会为每次 shell tool 启动；默认模式减少的是命令改写和变量可见性，不是 Hook 进程开销。配置无效时该次 Hook 不改写命令，也不阻塞工具。

### 为什么命令前会出现环境变量赋值

当命令符合上述注入范围时，`PreToolUse` Hook 会在 Agent 提交的 shell 命令前自动设置 `LORELUM_HOST_KEY=codex` 和 `LORELUM_HOST_SESSION_ID=<当前会话 ID>`：macOS/Linux 使用 `export`，原生 Windows PowerShell 使用 `$env:`。这不是 Agent 手写的命令，也不是登录凭据；它们让命令及其本地子进程中的 `lore get` 知道应该把候选提示记到哪个会话。记录的是 Practice 的 ID、标题等元数据和读取时间、工作目录，不是 Practice 正文、对话内容或整条 shell 命令。

这两个变量不会作为 Lorelum 的额外指导注入给 Agent；不过改写后的命令可能显示在 Codex 的工具详情或记录中，命令主动输出环境变量时也会进入工具结果，因此不能保证它们完全不出现在可见记录或模型上下文里。它们只用于会话关联，不要求 Agent 使用或管理。

Codex 现在只需要 `PreToolUse`，Plugin 不再安装空跑的 `PostToolUse` Hook。关闭 Pre 后，新的 `lore get` 无法关联当前会话，子 Agent 就收不到这些新读取的候选提示；`lore get` 本身和 Pack Catalog 仍可使用。如果从旧版 Plugin 更新后仍看到 Post Hook，重新审阅并安装当前 Plugin 配置。macOS 已在真实 Codex 中验证；Linux/Windows 的宿主级继承与审批流程仍待验证。

## 更新

```sh
codex plugin marketplace upgrade lorelum-plugins
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 提示 Hook 有变化，请重新审阅，然后启动一个新任务。

## 排查问题

如果 Codex 看起来没有使用 Lorelum：

1. 确认 Plugin 已安装并启用。
2. 确认 Codex 运行环境中的 `lore --version` 可用。
3. 如果 Codex 提示需要审阅，重新确认 Hook。
4. 安装或更新后启动一个新任务。

检索或模型问题请查看[故障排查](./troubleshooting)。
