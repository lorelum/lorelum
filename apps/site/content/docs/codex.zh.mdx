Lorelum Plugin 会在当前任务需要工程判断时，让 Codex 使用相关的工程指导。

## 开始前

请先完成[快速开始](./quickstart)。运行 Codex 的环境需要能使用 `lore` 命令，并且至少安装了一个 Pack。

## 安装

```sh
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 要求审阅 Hook，请确认后再启动一个新任务。

### 从早期 alpha 迁移

如果此前安装过 `lorelum@lorelum`，请先移除旧 Plugin 和旧 marketplace source，再安装当前版本：

```sh
codex plugin remove lorelum@lorelum
codex plugin marketplace remove lorelum
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

## 使用 Lorelum

在新任务中，要求 Codex 在确定重要的计划或实现决定前使用 Lorelum。例如：

```text
请在确定这个改动的计划前，用 Lorelum 查找相关指导。
```

Codex 是第一个接入[会话已读候选](./agent-setup#会话中的已读候选)的宿主：shell `PreToolUse` 为符合条件的命令传递会话身份，`SubagentStart` 可以给新子 Agent 展示候选元数据。这是 Lorelum 共用能力的首个宿主适配，不是 Codex 专属功能。哪些 shell 命令会得到身份，由[共享的 Agent 配置](./configuration#agent-shell-会话身份)决定。目前主 Agent compact 后仍不会自动恢复候选。

### 为什么命令前会出现环境变量赋值

当命令符合注入范围时，Codex 的 `PreToolUse` Hook 会在 shell 命令前设置 `LORELUM_HOST_KEY=codex` 和 `LORELUM_HOST_SESSION_ID=<当前会话 ID>`：macOS/Linux 使用 `export`，原生 Windows PowerShell 使用 `$env:`。这不是 Agent 手写的命令，也不是登录凭据；它们让命令及其本地子进程中的 `lore get` 知道应该把候选记到哪个会话。

这两个变量不会作为 Lorelum 的额外指导注入给 Agent；不过改写后的命令可能显示在 Codex 的工具详情或记录中，命令主动输出环境变量时也会进入工具结果，因此不能保证它们完全不出现在可见记录或模型上下文里。它们只用于会话关联，不要求 Agent 使用或管理。

Codex 现在只需要 `PreToolUse`，Plugin 不再安装空跑的 `PostToolUse` Hook。关闭 Pre 后，新的 `lore get` 无法关联当前会话，子 Agent 就收不到这些新读取的候选提示；`lore get` 本身和 Pack Catalog 仍可使用。如果从旧版 Plugin 更新后仍看到 Post Hook，重新审阅并安装当前 Plugin 配置。macOS 已在真实 Codex 中验证；Linux/Windows 的宿主级继承与审批流程仍待验证。

## 更新

```sh
codex plugin marketplace upgrade lorelum-plugins
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 提示 Hook 有变化，请重新审阅，然后启动一个新任务。

## 排查问题

如果 Codex 看起来没有使用 Lorelum：

1. 确认 Plugin 已安装并启用。
2. 确认 Codex 运行环境中的 `lore --version` 可用。
3. 如果 Codex 提示需要审阅，重新确认 Hook。
4. 安装或更新后启动一个新任务。

检索或模型问题请查看[故障排查](./troubleshooting)。
