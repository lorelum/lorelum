Lorelum Plugin 会在当前任务需要工程判断时，让 Codex 使用相关的工程指导。

## 开始前

请先完成[快速开始](./quickstart)。运行 Codex 的环境需要能使用 `lore` 命令，并且至少安装了一个 Pack。

## 安装

```sh
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 要求审阅 Hook，请确认后再启动一个新任务。

### 从早期 alpha 迁移

如果此前安装过 `lorelum@lorelum`，请先移除旧 Plugin 和旧 marketplace source，再安装当前版本：

```sh
codex plugin remove lorelum@lorelum
codex plugin marketplace remove lorelum
codex plugin marketplace add lorelum/lorelum
codex plugin add lorelum@lorelum-plugins
```

## 使用 Lorelum

在新任务中，要求 Codex 在确定重要的计划或实现决定前使用 Lorelum。例如：

```text
请在确定这个改动的计划前，用 Lorelum 查找相关指导。
```

当 Plugin 和 CLI 都更新到包含这项功能的版本后，shell tool 中成功执行的 `lore get` 可以为当前对话留下简短候选提示；脚本或管道中执行也一样。非 shell tool 会直接跳过。启动子 Agent 时，它可能看到候选 ID、标题和适用条件，再自行决定是否读取。提示不是 Practice 正文，也不代表主 Agent 已采纳它；Hook 不自动 query 或 `get`，目前也不会在主 Agent compact 后恢复这些提示。

这份可选列表由现有本机 Backend 管理，存放在 `~/.lorelum/sessions/<宿主>/<会话 ID>/practice-reads.jsonl`；目录直接使用宿主的会话 ID，将来也可以分别存放其他会话数据。删除 worktree 或重启 Backend 不会清掉已记录的候选。macOS 上，已信任的 Bash Hook 将会话 ID 传给命令，本地脚本和管道也能继承；它不会在每条 shell 命令前连接 Backend。成功的 `get` 只向已经运行的 Backend 报告。Hook 未获信任或命令主动清空环境时，可能漏记。Linux 和 Windows 暂时沿用 shell Pre/Post 活动窗口：打开窗口和报告读取时 Backend 都需要已经运行；同一路径下多个对话同时工作时，这条后备路径可能漏记或误归属。上述情况都不影响 `get` 的结果。使用提示前仍应通过 `lore get <practice-id>` 核对是否适用，不要把候选列表当成任务记录或权限依据。

## 更新

```sh
codex plugin marketplace upgrade lorelum-plugins
codex plugin add lorelum@lorelum-plugins
```

如果 Codex 提示 Hook 有变化，请重新审阅，然后启动一个新任务。

## 排查问题

如果 Codex 看起来没有使用 Lorelum：

1. 确认 Plugin 已安装并启用。
2. 确认 Codex 运行环境中的 `lore --version` 可用。
3. 如果 Codex 提示需要审阅，重新确认 Hook。
4. 安装或更新后启动一个新任务。

检索或模型问题请查看[故障排查](./troubleshooting)。
