Knowledge Pack 是一组带版本的 Practice。安装与你的工作相关的 Pack；Agent 描述任务和当前时刻时，Lorelum 会从中检索候选指导。

## 官方 Pack

生态目前还很小，Lorelum 维护四个官方 Pack：

| Pack             | 版本    | 内容                                     |
| ---------------- | ------- | ---------------------------------------- |
| `agentic-coding` | `0.5.1` | 34 条带明确停止点的步骤式决策 Practice，覆盖规划、实现、证据、恢复和交付 |
| `pack-creator`   | `0.2.0` | 27 条关于项目本地 Pack、编写、评审与 Registry 发布的 Practice |
| `react-web-craft` | `0.1.0` | React Web 应用设计与性能：组件状态、异步数据流、代码加载、渲染与组合 |
| `issue-pr-etiquette` | `0.1.0` | 可验证的单问题 Issue、单范围 PR、审查沟通与诚实披露 AI 协助 |

```sh
lore pack install agentic-coding
lore pack install pack-creator
lore pack install react-web-craft
lore pack install issue-pr-etiquette
```

默认安装会解析 Registry 中最新发行版；只有在需要稳定复现时才指定固定版本。浏览本地安装内容：

```sh
lore pack list --details
lore pack list agentic-coding
```

第一条命令列出 Pack 元数据，第二条列出某个 Pack 中的 Practice；两者都不是整个生态的可用 Pack 目录。[官方 Pack 仓库](https://github.com/lorelum/lorelum-packs)包含源码和发布记录。更新、卸载、Registry、本地目录与 Store 选项见 [Pack 命令](./reference/packs)。

## 选择 Registry 来源

Lorelum 内置 `official` Registry，指向官方 Pack 仓库。你也可以为团队或社区保存命名的
Registry，之后只使用 alias，不必每次重复输入 locator：

```sh
lore registry add team https://git.example.com/acme/team-packs.git
lore registry add local-team --path ../team-packs
lore registry list
lore registry set-default team

lore pack install team-pack
lore pack update team-pack@0.2.0
```

默认来源是显式的：不传 `--registry` 时，install/update 使用保存的 default；未设置时使用
`official`。`--registry team` 只为本次命令选择已保存 alias，`--registry <git-locator>` 只为
本次命令选择远程 source，不会自动保存。使用 `lore registry set-default official` 回到内置
来源，或用 `lore registry remove team` 删除保存的 source。删除当前 default 后也会恢复为
`official`。Lorelum 不会搜索其他 source，也不会在选中的 source 不可用时静默回退。

`lore registry add` 会先读取并校验 Registry descriptor，成功后才保存 alias。`lore registry list`
只读取本地 catalog，不访问远端。catalog 是用户级状态，保存在 `~/.lorelum/registries.yaml`；
它与选中的 Store 分离，不会随 `--store-root` 复制。Lorelum 不保存凭据。local Registry 的
worktree 路径属于私有 catalog 数据，不会出现在公开命令结果中。

### 远程 Git locator

默认平台是 GitHub，但 Registry 可以来自任何能通过安全 HTTPS 或 SSH endpoint 访问的 Git 仓库：

```sh
# GitHub shorthand 和规范 HTTPS 保留官方来源的历史行为。
lore pack install team-pack --registry acme/team-packs
lore pack install team-pack --registry https://github.com/acme/team-packs.git

# 其他 Git 平台使用 Git transport。
lore pack install team-pack --registry https://gitlab.com/acme/team-packs.git
lore pack install team-pack --registry ssh://git@git.example.com:2222/platform/team-packs.git
lore pack install team-pack --registry git@gitea.example:team/packs.git
```

参数必须指向 Git 仓库，而不是网页或 raw descriptor 文件。Lorelum 接受 `https://`、`ssh://`
和 SCP 风格 SSH（`user@host:path`）locator；拒绝 `http://`、`file:`、`git://`、remote helper、
带 URL 凭据的地址、query/fragment，以及直接指向 `.lorelum/registry.yaml` 的 URL。GitHub shorthand
或规范 GitHub HTTPS locator 为兼容性继续使用公开 raw descriptor；其他合法 remote 通过非交互、
受限的 Git 操作读取 descriptor。第一种 transport 失败后不会猜测第二种 transport。

私有仓库的 Git/SSH 访问由你在 Lorelum 外配置，例如 SSH key、`ssh-agent` 或宿主的 SSH 配置。
Lorelum 不会索取、打印或保存凭据；不要把 token 或密码写进 locator。公开 HTTPS 仓库无需凭据
即可使用。如果返回 `registry.unavailable`，请用同一个非交互 Git/SSH 身份确认选中的仓库可访问，
并确认其中有有效的 `.lorelum/registry.yaml`，然后重试。仓库不存在和没有权限可能有意返回同一个
公开错误。

### Local Git Registry 与本地 Pack 目录

两者是不同的 source 类型：

- `lore registry add <alias> --path <worktree>` 注册一个 local Git worktree，要求其 `HEAD`
  中包含 `.lorelum/registry.yaml`；之后可用 `--registry <alias>` 选择，或将它设为 default。
- `lore pack install --path <directory>` 与 `lore pack update --path <directory>` 直接读取一个
  Pack 目录；它不要求 Git，也不要求 Registry descriptor。

Pack 的 `--path` 形式是一次性的：不会保存路径、watch 目录，也不会在文件变化后自动更新已安装
Pack。路径相对于命令执行时的 cwd 解析。`pack install --path` 保留正常的 install/index 行为，
`pack update --path` 保留正常的 update 行为。不能把 `--path` 与 Pack specifier 或 `--registry`
混用。

目录无法打开时，修正路径后重试（`source.unavailable`）；目录可打开但不是有效 Pack 时，修正
`pack.yaml` 或 Pack 内容后重试（`pack.invalid`）。两种结果都不会包含本地 source 路径，且无效
本地 source 不会改动已经安装的 Pack。

Registry 命令以文件系统实际允许的读写操作为准，不要求已有 catalog 或其父目录采用特定
权限值，也不会修改目录权限。catalog 不存在时直接使用内置 `official`，不会为了读取默认源
创建 catalog 文件。

如果 `lore registry` 返回 `registry.catalog-invalid`，检查 catalog 是否可访问、是否为普通
文件而非符号链接。内容损坏时，先私下备份 `~/.lorelum/registries.yaml`，修复或移开损坏的
catalog，再重新运行 `lore registry list`。已经安装的 Pack 不受影响。临时的
`registry.catalog-busy` 可以直接重试。

## 更新或移除 Pack

使用 `lore pack update <pack-name>@<version>` 将已安装 Pack 更新到指定版本。Pack 内容保存与派生索引工作分别处理；确认新内容可检索前，检查 `data.indexSync`。

使用 `lore pack remove <pack-name>` 从所选 Store 中移除 Pack，其他已安装 Pack 仍然可用。响应字段和错误处理见 [Pack 命令](./reference/packs)。
