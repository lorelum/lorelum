本指南从可运行的 CLI 开始，带你读取第一条完整 Practice。Alpha 提供 macOS Apple Silicon、Linux x64 和 Windows x64 的预编译发行包；对应平台的安装命令和支持范围见[安装](./installation)。

## 让 Agent 完成设置

将完整设置交给能执行命令的 Agent：

```text
请根据 https://lorelum.com/zh/docs/agents.md 为当前项目配置 Lorelum v0.1.0-alpha.2。
安装 CLI 和 agentic-coding Pack，为当前宿主接入 Lorelum Skill；开始实际工作前，
完成一次自然语言检索和 Practice 全文读取来验证配置。
```

## 1. 检查 CLI

安装后运行：

```sh
lore --version
```

Lorelum 以可读 text 显示已安装的工具/协议版本。自动化需要 envelope 时使用 `lore --version --json`；请在 Agent 实际使用的命令环境中检查任一形式。

## 2. 安装 Knowledge Pack

官方 `agentic-coding` Pack 覆盖规划、实现、验证、恢复和交付中的工程判断：

```sh
lore pack install agentic-coding
```

安装会保存 Pack，并启动所需的 semantic index 工作。默认 text 会完整显示 index 状态，Agent 直接阅读即可。Pack 已安装时，模型准备或索引构建仍可能尚未完成；只有状态异常、需要 protocol 级排查时才使用 `--json`。具体字段见 [Pack 命令](./reference/packs)。

## 3. 描述任务和时刻

```sh
lore query "我正在按现有设计实现设置卡片，准备确定改动范围、实现计划和验证方式。"
```

可用的查询结果会显示与 JSON 相同的 Practice ID、title 和 applicability 字段。Agent 直接阅读默认 text，不解析其排版；只有结果异常、需要排查时才使用 `--json`。

首次 query 可能在本地模型下载或加载期间返回 `data.state: "preparing"`。等待加载后重试：

```sh
lore model load
```

如果 query 返回 `semantic.index-not-ready`，运行 `lore index build`。若构建返回 operation ID，使用 `lore index operation <operation-id>` 检查，直到完成后再重试 query。准备失败和其他错误见[故障排查](./troubleshooting)。

## 4. 读取 Practice

将占位符替换为查询结果中的 `practiceId`：

```sh
lore get <practice-id>
```

读完具体指导和适用条件。摘要用于选择，正文才是实际应用的依据。在这个示例中，可用相关指导明确设置卡片的需求范围，并选择与改动风险相称的验证方式。

## 5. 接入 Agent

按[接入 Agent](./agent-setup)安装 Lorelum Skill；使用 Codex 或 ZCode 时，分别安装 [Codex Plugin](./codex) 或 [ZCode Plugin](./zcode)。在新任务中向 Agent 发出指令：

```text
规划这次改动前先使用 Lorelum。描述当前任务和需要做出的判断，
检索相关 Practice，并完整阅读准备采用的指导。
说明这些指导如何影响实现计划。
```

接下来可阅读[检索与应用 Practice](./retrieval)了解查询方法，或通过[安装与管理 Pack](./packs)选择更多工程知识。
