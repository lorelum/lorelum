The Lorelum Plugin adds engineering guidance and the `/lore` command to ZCode.

## Before you start

Complete [Quickstart](./quickstart). The `lore` command must be available to
ZCode, and you need at least one installed Pack.

## Install

1. In ZCode, open **Settings → Plugin Management → Discover**.
2. Select **+** and add the Lorelum repository (`lorelum/lorelum`) or your
   local checkout as a marketplace.
3. Install **Lorelum** from `lorelum-plugins`.
4. Start a new session.

## Use Lorelum

Check that `/lore` appears in the command menu. You can run:

```text
/lore How should I verify this change?
```

Or ask ZCode to use Lorelum before it finalizes an important decision.

## Session read hints

ZCode participates in [session read hints](./agent-setup#session-read-hints): its `PreToolUse` Hook passes session identity to eligible Bash commands, so a successful `lore get` can record what was read for that conversation. ZCode offers no subagent-start event, so this host records candidates but does not show them to new subagents, and the Pack Catalog shown at session start is not a read hint. The shared [Agent shell setting](./configuration#agent-shell-session-identity) controls which shell commands receive identity.

When a Bash command is in the selected injection scope, the Hook sets `LORELUM_HOST_KEY=zcode` and `LORELUM_HOST_SESSION_ID=<current session ID>` before the command with a Unix `export` on every platform, because ZCode's Bash tool is a POSIX shell (Git Bash on Windows). The agent did not write those lines, and they are not login credentials; they only let `lore get` in the command or its local child processes associate a read with the right conversation. The rewrite never approves anything on its own: it changes the command text only and leaves ZCode's approval flow untouched. ZCode itself selects the shell its Bash tool runs commands in — normally the auto-detected Git Bash on Windows — and announces the resolved shell in the session context (for example, "The Bash tool shell is Git Bash."). The assignments use Unix `export` syntax because they target exactly that shell. If your session runs the Bash tool under a different dialect (a shell changed through ZCode's own selection, or a machine where no POSIX shell is found), the assignments do not take effect and the read is simply not recorded; the announced shell line tells you which shell is active.

## Supported features and limits

ZCode provides the Skill, CLI query/get, Main Pack Catalog at startup/resume, and successful-read association. It does not provide child read hints or a separate child Catalog.

Main read candidates are **not refreshed after compact**. ZCode's `SessionStart` runs at startup/resume only, with a per-session execution marker; its Hook events contain no post-compact context entry. A `compact` matcher cannot create that missing event. Candidates remain recorded, but recording is not automatic delivery to Main. Query/get useful guidance normally after context loss. See the [host capability table](./agent-setup#host-capabilities).


## Update

Open **Settings → Plugin Management**, select Lorelum, and install the offered
update. For a local checkout, uninstall and reinstall it from Discover after
you change Plugin files. Session read hints also need a `lore` CLI that knows
the ZCode `PreToolUse` event; an older CLI degrades it to a harmless no-op.
Start a new session after updating so the new Hook is loaded.

## Troubleshoot

If `/lore` or guidance is missing:

1. Confirm Lorelum is installed and enabled in Plugin Management.
2. Confirm `lore --version` works in the environment used by ZCode.
3. Start a new session after installing or updating.

For retrieval or model problems, see [Troubleshooting](./troubleshooting).
