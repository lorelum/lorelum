Lorelum 为 AI 编码 Agent 检索工程指引。它把可复用的工程经验组织成 **Practice**：离散、可检索、带适用条件的指导。**Knowledge Pack（知识包）** 将多条 Practice 组织成可安装、可分享的版本化集合，后文简称 Pack。

调用方描述 Agent 正在做什么、即将做出什么判断。Lorelum 从已安装 Pack 中检索相关 Practice 摘要，Agent 读取全文后，再将指导用于当前任务。

专业团队可以维护自己的标准；vibe coder 和小团队也可以从共享 Pack 开始，不必先独自发现所有工程反模式。

## 围绕任务和时刻检索

有效的查询同时说明当前工作和需要做出的判断：

```sh
lore query "我正在按现有设计实现设置卡片，准备确定改动范围、实现计划和验证方式。"
```

使用结果中的 `practiceId` 读取完整 Practice：

```sh
lore get <practice-id>
```

同一任务在规划、实现、恢复和验证时，可能需要不同的指导。判断发生变化时可以再次检索，无需在每条命令前机械调用。具体方法见[检索与应用 Practice](./retrieval)。

## 核心概念

| 概念           | 含义                                                              |
| -------------- | ----------------------------------------------------------------- |
| Practice       | 独立完整的工程指引，说明适用条件、具体做法和需要避免的反模式。    |
| Knowledge Pack | 围绕某个领域、技术栈或团队标准组织的版本化 Practice 集合。        |
| Store          | 本地已安装 Pack 及其派生索引的存储位置。                          |
| Skill          | 指导 Agent 判断何时检索、如何应用 Practice 的说明。               |
| Plugin         | 面向具体 Agent 宿主的集成，包含 Skill 和受支持的宿主原生行为，例如 Hook 或 extension。 |

默认自然语言检索使用本地 embedding 模型；也可以明确选择离线关键词检索。两者都检索所选 Store 中的 Pack，不搜索互联网。

## Lorelum 的职责

Lorelum 负责检索和排序 Practice。调用方负责描述任务与时刻、读取指导，并结合仓库事实和用户要求判断如何应用。

Lorelum Core 不管理任务、不读取完整会话，也不自行推断宿主生命周期事件。[宿主 Plugin](./agent-setup) 在受支持的生命周期事件或模型请求中提供 Pack 路由元数据；宿主功能对比说明哪些 Agent 能收到目录，以及哪些宿主能向子 Agent 传递已读候选。目录或候选提示都不代表 Agent 已遵循某条 Practice。[为什么需要 Lorelum](./why-lorelum)说明它要解决的知识与判断缺位。

> Lorelum 处于 public alpha。更新共享环境前，请阅读 [Alpha 兼容性](./alpha)。
