Lorelum 默认即可使用。用户级配置保存在 `~/.lorelum/config.yaml`，并由所有 Store 共享。

## 自动更新检查

支持的 Agent 会话集成默认启用 Lorelum 发行版发现。检查运行在独立、短生命周期的后台进程中，正常命令不等待发行网络结果。成功结果复用 1 小时，失败冷却 15 分钟；运行不同 CLI 版本时有独立检查资格。已就绪的提示按“当前运行版本／目标版本”组合投递一次，不在每次调用中重播。交互和支持入口见[自动更新提示](./installation#agent-会话中的自动更新提示)。

同时关闭自动联网与提示：

```yaml
updates:
  autoCheck: false
```

这是布尔项，默认 `true`。删除或设为 `true` 可重新启用，不会清除提示历史；下一次合格调用读取改动，无需重启 Backend。配置无效或无法读取时跳过自动更新工作，不阻塞原命令。显式 `lore update` 和 `lore update --apply` 始终可用，每次重新查询发行版。

## Agent shell 会话身份

`agent.shellSessionInjection` 是支持 shell 会话绑定的 Agent 集成共用的配置，决定哪些 shell 命令会得到会话身份。默认 `lore-only`：只检查外层命令文本是否含独立的 `lore` 字样。直接调用、管道和命令替换中的 `lore` 都能匹配；Hook 不解析命令，也不读取脚本文件。例如外层只有 `sh script.sh` 时，即使脚本内部调用了 `lore get`，这次读取也可能无法关联到对话。反过来，外层文本只是提到 `lore` 也可能触发注入。

需要覆盖本地脚本内的间接调用时，在 `~/.lorelum/config.yaml` 加入：

```yaml
agent:
  shellSessionInjection: all-shell
```

`all-shell` 为每个受支持的 shell tool 命令传递身份，不影响非 shell tool。删除该字段或设为 `lore-only` 即恢复默认。支持此功能的 Hook 会在下一次调用时读取改动，无需重启 Backend。配置无效时，该次 Hook 不改写命令，也不阻塞工具。两种模式下 Hook 仍会在每次匹配的 shell 调用中运行；默认模式减少的是命令改写和变量可见性，不是 Hook 进程开销。

这是 Agent 共用配置，不属于 Codex。只有宿主 Plugin 支持 shell 会话绑定时才生效；单靠设置该字段不会新增 Hook。会话已读候选的共用行为见[接入 Agent](./agent-setup#会话中的已读候选)，具体支持的 Hook 以各宿主指南为准。

## omp 子 Agent Pack 目录

`agent.subagentPackCatalog` 仅由 omp 集成读取；Codex、Claude Code、Cursor、WorkBuddy 和 ZCode 不读取此配置，设置它不会改变这些宿主的行为。

在 [omp](./omp) 中，Main 始终获得 Pack Catalog。task/eval 子 Agent（包括嵌套层级）默认只收到 Main 成功读取 Practice 的有界摘要。希望子 Agent 也看到 Pack 目录时，将下面的配置合并到 `~/.lorelum/config.yaml` 已有的 `agent` 段：

```yaml
agent:
  subagentPackCatalog: true
```

这是布尔配置，默认 `false`；删除该字段或设为 `false` 即恢复默认。开启后只额外提供 Pack 名称、描述和适用范围等目录元数据，不注入完整 Pack 或 Practice 正文。不改变 Main 的 Catalog、候选查询或子 Agent 自己 get 的归属。所有嵌套子 Agent 都沿用源头 Main 的候选；它们自己的读取不会自动并入 Main。

CLI 在下一次子 Agent Catalog bridge 调用读取设置；新子 Agent 或下一次会话/compact 刷新采用新值，同一生命周期的普通请求仍复用临时快照，不反复读取目录。可以重新加载 omp 触发刷新，无需重启 Backend。子 Agent 不会仅因没有 Catalog 自动列出 Pack 补齐目录；任务确实需要独立发现材料时仍可按需查询或浏览。

## 选择 Store

用 `--store-root` 将项目的 Pack 和 index 单独保存：

```sh
lore --store-root /path/to/store pack install agentic-coding
lore --store-root /path/to/store query "认证改动应该怎样验证？"
```

安装、index、query 和 `get` 应使用同一个 Store root。这个选项只选择 Store 中的 Pack 数据，不会改变 query cache、模型、模型缓存、Backend 地址或 runtime 目录。

## Semantic 检索方法

Semantic query 默认使用 `single-vector`。单次查询可运行 `lore query "<text>" --mode multi-view-vector`（或 `--mode single-vector`），它覆盖方法选择，不校验被覆盖的方法项，也不写回文件；下一次普通 query 恢复配置的方法。若希望后续 query 和 index 命令默认使用实验方法，再加入：

```yaml
query:
  retrievalMethod: multi-view-vector
```

`single-vector` 将一个完整文档向量与一个查询向量比较。`multi-view-vector` 使用每条 Practice 的多个视图；它是实验方法，不保证排名更好。设为 `retrievalMethod: single-vector` 或删除该字段即可恢复默认。只接受这两个 ID；`simple` 和 `multi-view` 不是别名。

下一次 semantic query、`index status`、`index build`、`index rebuild` 或安装后的 index synchronization 都会读取当前选择，无需重启 Backend。每种方法的 index 与 progress 状态独立；切回时可以复用兼容的缓存工作。详见 [Index 命令](./reference/indexing)。

同一次 query 或 index 命令（包括安装后的 index synchronization）中，logging 与检索设置共享该次调用首次读取的配置文档。读取后发生的编辑从下一次调用生效，不会在当前命令中途混用新值；各消费者仍只校验自己使用的设置。

读取该配置的命令遇到非法值会返回 `query.config-invalid`；修正或删除该字段即可。`--mode single-vector` 与 `--mode multi-view-vector` 可为一次 query 覆盖该方法值，但不会绕过其他配置错误；配置为 `multi-view-vector` 时，`--mode single-vector` 可为一次 query 与默认方法对比。`lore query "<text>" --mode keyword` 仍是离线路径，不读取或校验 semantic 方法。不需要独立的方法 flag 或环境变量。

## Query cache 与等待策略

cache 是用户级、可删除重建的派生数据，默认在 `~/.lorelum/cache`，不会写入 `.lorelum/`、Git metadata 或 LocalStore。使用 `--cache-root <path>` 为一次 query/index/cache 命令选择隔离 cache。在兼容的检索方法与模型配置下，相同最终 Practice 语料会复用 artifact 与 embedding vector；目录路径、Git、worktree、branch、commit 和 mtime 不参与 artifact ID。

```yaml
query:
  maxWaitMs: 3000
  minCoveragePercent: 0
```

两个值分别是 `0–120000` 的整数毫秒和 `0–100` 的整数百分比。超出 `maxWaitMs` 时，后台 operation 继续；已验证 current progress 达到 `minCoveragePercent` 时，query 可以返回 partial result。运行 `lore cache status` 查看大小与 progress，运行 `lore cache prune` 显式删除未被 build/query 使用的 derived state。

## 本地模型

默认 query 和 semantic index 使用固定的本地 embedding 模型。Lorelum 按需下载并复用缓存文件，缓存位于 `~/.lorelum/models/`。

```sh
lore backend start
lore model status
lore model load
lore model unload
```

独立运行 model 命令需要 Backend 已启动，因此提前准备模型时先运行 `backend start`。`load` 等待模型准备和加载完成；`unload` 释放运行时，但保留模型缓存。详见 [Model 命令](./reference/model)。

## 本地服务

semantic 检索需要服务时，Backend 会自动启动。修改模型或 Backend 配置后可以用以下命令检查或重启；切换 `query.retrievalMethod` 不需要重启：

```sh
lore backend status
lore backend stop
lore backend start
```

Backend 或模型配置无效时会明确报错，修改后需要重启 Backend；Agent Hook 的配置在下一次 Hook 调用时生效，检索方法在下一次相关命令时生效。

## 模型设置

需要覆盖默认值时，在 `config.yaml` 中加入 `embedding`：

```yaml
embedding:
  threads: 4
  download:
    enabled: true
    connectTimeoutSeconds: 30
    stallTimeoutSeconds: 60
    maxAttempts: 3
```

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `embedding.modelPath` | 未设置 | 固定模型文件的绝对路径；Lorelum 会验证，但不会覆盖该文件。 |
| `embedding.cacheDirectory` | `~/.lorelum/models` | 未设置 `modelPath` 时使用的缓存绝对路径。 |
| `embedding.threads` | `4` | CPU 线程数，范围 1–64。 |
| `embedding.download.enabled` | `true` | 缺少模型时是否允许下载。 |
| `embedding.download.url` | 内置固定来源 | 同一模型文件的 HTTPS 镜像，需支持断点续传。 |
| `embedding.download.connectTimeoutSeconds` | `30` | 各连接阶段的超时秒数。 |
| `embedding.download.stallTimeoutSeconds` | `60` | 连续没有收到文件字节的最长秒数。 |
| `embedding.download.maxAttempts` | `3` | 临时网络错误的尝试次数。 |

自定义路径或镜像必须提供固定的 Q4_0 模型：66,345,216 字节，SHA-256 为 `18e8ce8ce834790618e90d26bed465cca87362076f3042eb0d8eee0732596f59`。它不能用来选择其他模型。禁用下载且没有有效模型时，加载返回 `embedding.not-configured`。

## 服务设置

```yaml
backend:
  startupTimeoutMs: 10000
  requestTimeoutMs: 5000
  shutdownTimeoutMs: 5000
```

三个值均为 1–120000 的整数，单位毫秒。以下环境变量可以覆盖 YAML：

- `LORELUM_BACKEND_STARTUP_TIMEOUT_MS`
- `LORELUM_BACKEND_REQUEST_TIMEOUT_MS`
- `LORELUM_BACKEND_SHUTDOWN_TIMEOUT_MS`

startup 控制服务与 native runtime 启动，request 控制单次请求，shutdown 控制卸载与停止。模型文件的下载时间由上面的下载设置控制。

Backend 只在启动时读取一次这些设置。修改 YAML 或环境变量不会改变正在运行的实例；重启 Backend 后才会生效。`backend status`、`backend stop` 和 model 命令不会写入配置文件。
