Lorelum Plugin 为 WorkBuddy 带来工程指引与 `/lore` 命令。

## 开始之前

先完成[快速开始](./quickstart)。`lore` 命令必须对 WorkBuddy 可用，并且至少安装一个 Pack。

## 安装

1. 在 WorkBuddy 的插件/市场管理中，将 Lorelum 仓库（GitHub 上的 `lorelum/lorelum`）添加为第三方市场，然后从 `lorelum-plugins` 市场安装 **Lorelum**。

2. 或者使用 WorkBuddy 内嵌的 CodeBuddy CLI 直接从 GitHub 安装，无需先把仓库克隆到本地：

   ```sh
   export WORKBUDDY_CONFIG_DIR=~/.workbuddy CODEBUDDY_CONFIG_DIR=~/.workbuddy
   codebuddy plugin marketplace add https://github.com/lorelum/lorelum
   codebuddy plugin install lorelum@lorelum-plugins
   ```

   注意：不带环境变量直接运行只会写入独立 CLI 的注册表（`~/.codebuddy`），而桌面端客户端读取的是 `~/.workbuddy`，所以必须先重定向配置目录；安装完成后还要完全退出并重启 WorkBuddy，常驻进程才会重新加载插件注册表。开发者预览本地检出时，可把上行的仓库 URL 换成本地仓库根目录路径（目录内须含 `.codebuddy-plugin/marketplace.json`；传 `.codebuddy-plugin` 目录或 manifest 文件路径会被拒）。`codebuddy` 是 WorkBuddy 安装目录内嵌的 CLI（Windows 位于安装目录下的 `resources/app.asar.unpacked/cli/bin/codebuddy`），按你的平台调整调用路径。

3. 开始一个新任务。WorkBuddy 会在会话开始时收到已安装的 Pack 目录。

## 使用 Lorelum

确认 `/lore` 出现在 WorkBuddy 展示插件命令的位置。你可以运行：

```text
/lore 这个改动应该如何验证？
```

或在 WorkBuddy 最终确定重要决策之前，让它先用 Lorelum 检索相关指引。



WorkBuddy 会话还会记录已读 Practice 候选。当 agent 在会话内成功执行
`lore get` 时,CLI 会把该 Practice 的元数据报告给正在运行的 Backend,并写入
`~/.lorelum/sessions/workbuddy/<会话 ID>/practice-reads.jsonl`。上报是可选行为:
它不会启动 Backend,也不会改变 `lore get` 的结果。

当 WorkBuddy 的 Bash 工具执行含 `lore` 字样的命令时,命令前会被加入两行
`export`,携带宿主与会话身份 —— 已读记录正是借此关联到当前对话。该前缀不
改变命令的批准流程、参数或退出码,也不会注入到非 shell 工具。哪些命令会被
加前缀由共用的
[`agent.shellSessionInjection`](./configuration#agent-shell-会话身份) 配置决定。
WorkBuddy 的子 Agent 目前收不到已读候选提示:宿主会派发 SubagentStart 事件
但丢弃 hook 输出,因此该宿主没有可用的提示通道。

## 功能支持情况

WorkBuddy 提供 Skill、CLI query/get、Main Pack Catalog 和成功读取关联。手动和自动压缩复用已有 `SessionStart(source=compact)`，在任务继续前刷新 Main 的候选；startup/resume 不额外再发候选。

候选只是有界历史元数据，不是完整正文或采纳记录。有用时重新 `lore get`。候选为空或 Backend 不可用时保留 Catalog，不阻塞继续任务，也不为恢复提示自动启动 Backend。

子 Agent 已读提示和 Plugin 单独提供的子 Agent Catalog 均缺失；被宿主丢弃的子 Agent Hook 输出不是交付通道。完整差异见[宿主功能对比](./agent-setup#宿主功能对比)。


## 更新

打开插件管理界面，选择 Lorelum 并安装提供的更新。对本地检出而言，修改 Plugin 文件后请从你的市场卸载并重装。

## 排障

如果 `/lore` 或指引缺失：

1. 确认 Lorelum 已在插件管理中安装并启用。
2. 确认 `lore --version` 在 WorkBuddy 使用的环境中可用。
3. 安装或更新后，开始一个新任务。

检索或模型问题参见[故障排查](./troubleshooting)。
