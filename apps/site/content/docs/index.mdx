Lorelum retrieves engineering guidance for AI coding agents. It turns reusable experience into **Practices**: discrete instructions with explicit applicability conditions. **Knowledge Packs**, or Packs, organize those Practices into versioned collections that you can install and share.

Describe what the agent is doing and the decision it is about to make. Lorelum searches installed Packs and returns relevant Practice summaries. The agent reads the full guidance before using it in the task.

Teams can bring their own standards. Vibe coders and small teams can start with shared Packs without first having to discover every engineering anti-pattern themselves.

## Retrieve for the task and moment

A useful query includes both the work and the judgment it requires:

```sh
lore query "I am implementing a settings card from an existing design. I am about to define the scope, implementation plan, and validation."
```

Use a returned `practiceId` to read the complete Practice:

```sh
lore get <practice-id>
```

The same task may need different guidance during planning, implementation, recovery, and verification. Retrieve again when the decision changes; querying before every command is unnecessary. See [Retrieve and apply Practices](./retrieval).

## Core concepts

| Concept | Meaning |
| --- | --- |
| Practice | A self-contained unit of engineering guidance, including when it applies and which anti-patterns to avoid. |
| Knowledge Pack | A versioned collection of Practices scoped to a domain, stack, or team standard. |
| Store | The local installation of your Packs and the indexes derived from them. |
| Skill | Instructions that help an agent decide when to retrieve and how to apply Practices. |
| Plugin | A host integration that packages a Skill and supported host-native behavior, such as Hooks or extensions. |

Natural-language retrieval runs locally with an embedding model. Keyword retrieval is available explicitly for offline term matching. Both search the Packs in the selected Store; neither searches the web.

## What Lorelum is responsible for

Lorelum retrieves and ranks Practices. The caller describes the task and moment, reads the guidance, and decides how it applies alongside the repository and the user's request.

Lorelum Core does not manage the task, inspect the full conversation, or infer host lifecycle events. [Host Plugins](./agent-setup) provide Pack routing metadata at supported lifecycle events or model requests; the host capability comparison explains which agents receive it and which hosts can pass read candidates to subagents. Neither a Catalog nor a read hint proves that a Practice has been followed. See [Why Lorelum](./why-lorelum) for the knowledge-and-judgment gap this addresses.
