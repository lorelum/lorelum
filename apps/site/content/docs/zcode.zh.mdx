Lorelum Plugin 会为 ZCode 提供工程指导和 `/lore` 命令。

## 开始前

请先完成[快速开始](./quickstart)。运行 ZCode 的环境需要能使用 `lore` 命令，并且至少安装了一个 Pack。

## 安装

1. 在 ZCode 中打开 **Settings → Plugin Management → Discover**。
2. 点击 **+**，添加 Lorelum 仓库（`lorelum/lorelum`）或本地 checkout 作为 marketplace。
3. 在 `lorelum-plugins` 中安装 **Lorelum**。
4. 启动一个新会话。

## 使用 Lorelum

确认命令菜单中出现 `/lore`。你可以运行：

```text
/lore 这个改动应该怎样验证？
```

也可以要求 ZCode 在确定重要决定前使用 Lorelum。

## 会话中的已读候选

ZCode 参与[会话已读候选](./agent-setup#会话中的已读候选)：`PreToolUse` Hook 会在符合条件的 Bash 命令前传入会话身份，使成功的 `lore get` 能把读取记录关联到当前会话。ZCode 没有子 Agent 启动事件，因此该宿主只记录候选，不会向新启动的子 Agent 展示候选，会话开始时展示的 Pack Catalog 也不是已读提示。哪些 shell 命令会获得身份由共用的 [Agent shell 设置](./configuration#agent-shell-会话身份)控制。

当 Bash 命令在注入范围内时，Hook 会在命令前用 Unix `export` 设置 `LORELUM_HOST_KEY=zcode` 和 `LORELUM_HOST_SESSION_ID=<当前会话 ID>`；ZCode 的 Bash 工具在所有平台上都是 POSIX shell（Windows 上为 Git Bash），所以写法一致。这些行不是 Agent 写的，也不是登录凭据，只用于让命令或其本地子进程中的 `lore get` 把读取关联到正确的会话。改写本身不会替用户批准任何操作：它只修改命令文本，ZCode 的审批流程保持原样。ZCode 自身会为 Bash 工具选定执行命令的 shell——Windows 上通常是自动检测的 Git Bash——并在会话上下文中告知解析结果（例如 "The Bash tool shell is Git Bash."）。身份赋值使用 Unix `export` 语法，针对的正是这个 shell。如果你的会话让 Bash 工具运行在其他方言下（通过 ZCode 自己的 shell 选择改过，或机器上找不到 POSIX shell），赋值不会生效，该次读取只是不被记录；会话中告知的 shell 行可以确认当前生效的 shell。

## 功能支持情况与限制

ZCode 提供 Skill、CLI query/get、startup/resume 时的 Main Pack Catalog 和成功读取关联，不向子 Agent 提供已读提示或独立 Catalog。

**compact 后不刷新 Main 已读候选。** ZCode 的 `SessionStart` 只在 startup/resume 运行，并有会话级一次执行标记；其 Hook 事件没有压缩后上下文入口。写入 `compact` matcher 不会创造这个事件。候选会继续记录，但记录不等于自动交付 Main；上下文丢失后按任务照常 query/get。完整差异见[宿主功能对比](./agent-setup#宿主功能对比)。


## 更新

在 **Settings → Plugin Management** 中选择 Lorelum，安装可用更新。使用本地 checkout 开发时，修改 Plugin 文件后在 Discover 中卸载并重新安装。会话已读候选还需要能识别 ZCode `PreToolUse` 事件的 `lore` CLI；旧版 CLI 会把它降级为无害的 no-op。更新后请启动新会话以加载新的 Hook。

## 排查问题

如果没有出现 `/lore` 或工程指导：

1. 确认 Lorelum 已在 Plugin Management 中安装并启用。
2. 确认 ZCode 运行环境中的 `lore --version` 可用。
3. 安装或更新后启动一个新会话。

检索或模型问题请查看[故障排查](./troubleshooting)。
