# 方案 C：角色对齐检索与受控学习验证路线

> 日期：2026-10-03。读者：Lorelum 维护者与检索实验实现者。状态：待实验的分阶段研究计划，不是已验证结论或当前产品合同。本轮获准范围：本研究文档，以及现有 change 的设计与任务补充；未批准生产公式解冻、自动学习发布或 Profile 解耦。

## 1. 决策摘要

选择研究“保留任务角色与细粒度证据，再进行融合”，而不是继续调节旧 task-card/body 两个标量的比例。优先证明角色信息是否改善适用性判断，再实现自动 analyzer，最后才考虑离线受控学习。

成功目标是跨 Pack 使用共享规则、增量接入内容，并在任务条件相近的近邻竞争中保持可靠排序。不是要求所有 query 命中指定 ID，也不是承诺语料越多越准确、自学习永不偏移。

本计划的关键可否证假设：在编码模型、语料和检索边界不变的条件下，有来源的角色表示能增加区分“主题相近但当前不适用”与“当前适用”的证据，并在独立任务上带来收益。人工角色也无收益时，不投入自动 analyzer 或学习闭环。

关联边界：

- [总目标与阶段演进](./task-aware-retrieval-evolution.md)：探索背景，不覆盖当前单次全量检索约束。
- [现行 retrieval contract](../../openspec/specs/retrieval-query/spec.md) 与 [semantic index contract](../../openspec/specs/semantic-index/spec.md)。
- [现有 change 设计](../../openspec/changes/advance-task-aware-semantic-retrieval/design.md) 与 [分阶段任务](../../openspec/changes/advance-task-aware-semantic-retrieval/tasks.md)。
- [verification §21–24](../../openspec/changes/advance-task-aware-semantic-retrieval/verification.md)：已执行的诊断、否决与覆盖审计。

| 已有证据 | 向量存在较强公共分量，分数带宽狭窄，通用 Practice 形成 hub | 角色层可能受表示质量限制；不能以几何指标代替检索收益 |

| 已修正推理 | 首个 task-card 包含 anti-pattern；移除该文本会退化 | 保留正文、anti-pattern 与条件信息，不声称它们没参与排序 |

“范围过窄、样本不足”是目前证据外推的限制，不足以解释全部排序错误。角色分析、模型表示、语料触发边界与评分协议必须分别检查。

## 3. 实验硬边界

- 排名依据仍为向量余弦证据；融合权重非负。不能把负余弦强制当概率，也不引入负证据扣分。
- 每个条件对全部 eligible Practice 评分一次，K 最后应用；不截断候选、不进行 RRF、跨检索名次融合或多轮补召回。
- 没有 keyword/BM25/FTS5 或共享字符匹配通道。结构化 analyzer 可分析语言含义，但不得向排序提供词面重合分数。
- 生产 `scoreSemanticPractice` 与 golden pin 保持不变。C 的不同聚合只存在于隔离实验，不冒充生产修补。
- 不要求作者采用新的 Markdown 模板或增加公开 schema 必填字段；不修改 Pack 仓库内容来迎合目标 query。
- canonical 内容与 snapshot retry、index 兼容、staging 原子发布规则保持不变。
- 人工角色生成与检索阶段不访问 labels；完整排名持久化后，独立评分阶段才能读标签。
- 已见旧样本不能通过重新切分变成未见测试集。新任务必须在策略冻结前采集、标注与分配用途。

## 4. 表示结构：稳定契约与可变策略分离

```text
query 原文 ── 一次角色提取 ── 带来源的 query 角色向量
                                    ×
canonical Practice ── 离线投影 ── 带来源的证据向量
                                    ↓
                        角色 × 证据的余弦矩阵
                                    ↓
                   共享、非负、预先冻结的融合策略
                                    ↓
                     全量排序 → 最终 K → canonical 结果
```

### 4.1 Query 角色

建议内部接口使用 `intent / moment / artifact / constraints / domain`；允许角色缺失、同一片段多角色、多个动作和 `unknown`，不强求五项齐全。

| 角色        | 含义                       | 不能做的简化                             |
| ----------- | -------------------------- | ---------------------------------------- |
| intent      | 当前需要完成的动作或决定   | 只抽一个动词，丢掉决定对象               |
| moment      | 当前状态与事件先后关系     | 把“核实 finding”解释成“已经发生测试失败” |
| artifact    | 动作对象、已有产物         | 将提到安装对象等同于正在安装             |
| constraints | 改变适用性的必要条件或边界 | 默认视作应降权的背景                     |
| domain      | 技术与业务上下文           | 默认永远无关，或独自决定任务             |

最小实验记录应包含：角色、原文片段位置、角色文本、推断说明和分析版本。原文片段必须可重放；重述只能使用原文支持的事实，不补造状态、目标或约束。人工标注不伪造数值置信度；自动置信度须经单独校准，不能直接当作余弦适用概率。

多意图 query 暂保留多个动作与各自关联条件，不在首轮实现完整任务图。如果角色信息不足，保持未解析状态并使用预先声明的 control 路径；报告回退次数，不把不确定性变成硬排除。

### 4.2 Practice 证据

[公开 schema](../../packages/format/src/schema/practice.ts) 中 `stage` 为自由字符串，不是统一生命周期枚举。[正文投影](../../packages/engine/src/query/semantic/projection.ts) 处理自由 Markdown，标题不保证语义角色。

首轮先复用现有 task-card/body views，并为人工判读保留 schema 字段或正文块的来源。若要生成新的适用片段、角色视角或条件重述，必须作为单独 document intervention 编码，不能归因成仅 query 改进。

证据记录至少能追溯到 Practice、内容 digest、字段/正文块、投影版本和 encoder 身份。Practice ID 只用于归属、连接和既有确定性 tie-break，不进入 embedding，也不能成为学习特征。

不强制所有 body 块归为 guidance/risk/constraint。未识别角色的块仍是通用正文证据；不能因缺少某一人为角色而删掉 Practice。

### 4.3 融合策略

首轮不是训练任意神经排序器，也不学每条 Practice 的偏置。输入为余弦证据及有来源的角色关系，输出为单一最终分数；不得偷偷加独立相关性模型分数。

实施前须登记一个简单、确定性的候选策略，包括角色权重、组内归约、缺失角色/空通道处理、负余弦、重复证据、tie-break 和回退规则。权重在读取新测试标签前固定。不得基于 Pack 名称选择配方；不得在查看结果后不断搜索权重并用同一测试集宣布成功。

此文不虚构一个已证明有效的 C 公式。具体配方是阶段 G0 的待决产物，只有登记完成后才能开展正式比较。余弦地板很高时，“相似度高于阈值就满足条件”的门控可能全部开启，不默认采用。

## 5. 最小归因实验

按顺序隔离变化，先不同时重写 query、Practice 和公式：

| 条件 | 改变 | 保持不变 | 可以回答的问题 |
| --- | --- | --- | --- |
| Control | 无 | 冻结生产公式、query、文档表示、模型 | 基线是否逐分复现 |
| Q | 人工 query 角色文本与预登记角色权重 | 文档 views、生产组内归约、模型 | query 表示保留任务信息是否有效 |
| Q+I | 在 Q 上保留角色对证据组的交互，再用固定非负策略汇总 | Q 文本、现有文档向量、模型 | 细粒度交互是否有额外价值 |
| Q+I+D（可选） | 在上一条件上增加有来源的文档角色投影 | query、融合策略、模型 | 新文档判别信息是否必要 |
| Auto | 以自动 analyzer 替换有效的人工角色 | 文档、融合策略、模型与评测 | 自动化损失与运行成本 |

Q 不是完整 C；Q+I 对旧 views 的复用也不能凭空获得不存在的文档角色。必须分别记录每个条件的能力边界。若改用更高精度或另一 encoder，另开模型条件，并重编码兼容文档与 query；不混进角色效果，换模型需另立提案。

负对照优先使用不改变任务含义的背景追加、等义角色重述和同样处理预算的非角色文本处理，避免收益实际来自额外 token 或重述本身。任何随机化固定 seed，策略的预期失败路径同样报告。

## 6. 评测设计与解释规则

### 6.1 数据身份与标注

沿用 verification 中的冻结 v2 suite 与 `store-6bf1e1b-v4`，不用个人 Store。既有 50 例只承担开发诊断和回归。运行 manifest 记录代码/输入/投影/模型 digest、pooling、threads、编码预算、N/K、完整排名和环境身份；本机路径只进入本机 protocol，不提交私有 labels、原始 query 日志或运行缓存。

新增 pilot 建议先采集 24–40 条真实、有明确任务边界的 query，覆盖当前缺口、条件近邻和无相关目标；这是工作量建议，不是统计功效保证。不要求每个 query 都有答案，不照着目标 Practice 反向写问题。

新增标注协议单独版本化，区分：必需核心、充分可替代项、前置/补充帮助、无关项、禁项和未判定。v2 `coreIds` 不变；不能把替代项追加到“所有 core 都必须命中”的现有字段。无人能可靠判断的条目保留未判定，并记录评审分歧。

query 角色标注者不看目标 ID 或排名；Practice 证据标注面向全语料/预先固定的覆盖切片，不只加工答案。相关性标注是独立工作，可看 canonical 内容，但不看系统身份和条件排名顺序。若只能单人完成，披露非盲/依赖风险，不宣称独立验收。

对结果需要补判时，匿名合并各条件输出、打乱顺序并独立评审。该池只能产生新的补充审计，不修改原测试标签后重算“正式提升”；下一轮采用新协议时重新冻结。

### 6.2 分开报告维度

- v2 回归：hit@1/3/5、top-20、MRR、scope、forbidden-before-core、逐例改善/回归。
- 新协议：当前任务适用率、可接受答案覆盖、禁项、未判定比例与评审分歧；未判定不当作负例。
- 无相关目标：报告前 K 的适用/误导项；本计划不新增产品拒答阈值。
- 泛化：Pack/任务类型/语言/query 长度/多意图分组，组样本数一并给出。
- 成本：新增编码量、analyzer 延迟、评分与 IO、峰值内存、重试与回退；编码成本与查询成本分开。

pilot 不用一个总加权分掩盖质量、安全或成本回归。配对结果报告原始计数；重复改写的同源 query 视为同一任务簇，不能冒充独立样本。小样本结果只决定是否值得扩展，不支撑显著或普适提升的宣传。

### 6.3 默认进入/停止门槛

以下为该路线的保守门槛，正式运行前在 protocol 中锁定；若需调整，在看新测试结果之前完成并说明原因。

1. Control 对全部 query × Practice 的生产评分复算误差不超过 `1e-6`，且冻结指标一致，否则停止质量比较。
2. 新留出 pilot 的“前 5 有充分可接受答案且无已判禁项”成功数严格优于 control；已判禁项 query 数不得增加。所有条件的标注覆盖必须可比，否则为不确定。
3. 旧 v2 的 hit@5 不低于 45/50，MRR 不低于冻结 control，scope 不高于 2，forbidden-before-core 不高于 1；不允许只展示新增收益而隐藏旧损失。
4. 不新增已确认的高影响误导；小组为零收益或回归时逐例复审，不能因总分增长直接通过。
5. Analyzer/查询成本预算在 G0 根据实际设备和基线测量冻结；未填预算或未测成本，不进入产品接入。

这些门槛不是“永远不能有权衡”的产品定律。若某候选有明确收益但未通过，标记为 trade-off 或不确定，单独请求设计决定；不在实验后默默放宽。

## 7. 扩展性：内容增长、质量竞争与计算增长

### 7.1 新 Pack 接入

普通新增走共享投影和增量索引，不增加 Pack 专属角色、权重或 ID 规则。未知领域保留原文与通用证据，新 Pack 能被索引不等于已验证排序质量。

在仅有四个现有 Pack 的情况下，leave-one-Pack-out 只是有限泛化压力测试；已用于探索的 Pack 即使再次留出，也不能称全新领域验证。下一轮至少加入未参与策略设计的新内容或真实 Pack 样本。

新增近义 Practice 若没有清晰触发边界，需要 pack 作者改善内容；检索器不能替作者决定本来就模糊的适用契约。

### 7.2 增长压力集

保持 query 与策略不变，分别加入真实来源的：新领域内容、同主题但状态不适用的近邻、充分可替代答案，以及不新增判别信息的正文扩展。

逐步记录加入的 Practice/view 数与来源，分别观测旧核心名次、可接受集合覆盖、禁项和延迟。新增正确替代项挤掉旧 core 不必然是质量下降，应按冻结的新协议判断；v2 指定 ID 回归仍单独报告。不仅用复制相同文本的方式模拟内容增长。

### 7.3 计算边界

精确全量评分主要计算量约为 `query 角色数 × 总证据向量数 × 维度`；多角色不会消除线性增长。向量存储本体可按 `向量数 × 维度 × 每元素字节数` 估算，但还需 metadata、SQLite 与工作缓冲，不以估算代替峰值测量。

文档分析离线进行，query analyzer 每请求一次，禁止逐 Practice 调用大模型。控制角色/证据重复膨胀，逐步测批量读取和矩阵运算的价值；不通过静默丢弃尾部条件缩减预算。

[现有 reader](../../packages/engine/src/query/semantic/index/reader.ts) 逐 Practice 读取向量，尚无大规模容量证明；[增量索引](../../packages/engine/src/query/semantic/index/incremental.ts) 已有 digest 复用基础。未来性能优化只在测量后单独实施，仍保持全量评分和 snapshot 一致性。若目标容量超出预算，需重新讨论约束，不能声称学习解决复杂度。

## 8. 版本身份与迁移

长期希望区分文档表示身份、query 表示身份和融合策略身份，使普通内容更新增量编码、融合更新尽量复用文档向量。身份中仍需表达 encoder/pooling/normalization 与 query-document 兼容关系，不能只因维度相同就复用。

[当前 Profile](../../packages/engine/src/query/semantic/profile.ts) 的 hash 同时包含 document/query projection version。当前不能承诺改 analyzer 零重建；本阶段不拆 Profile。隔离 experiment manifest 使用独立版本标识，不篡改 active index metadata。

若最终需要持久化新角色 views，须先同步 Profile、schema/迁移、增量 digest、staging 验证和原子发布设计，并补 canonical/snapshot retry 回归，再接入 Store 与 ProjectContext 共用路径。

## 9. 受控学习：延后且不自动发布

只有固定策略与自动角色均通过前置关卡，且积累足够可信反馈后，才评估学习必要性。更多未标注 Practice 本身不是训练真值。

首选有理由的成对适用比较与明确纠错；点击、曝光、Agent 采用只作为弱观察。未采用不等于负例，模型自己的判断不回灌成 gold，不把检索日志默认上传或提交；反馈权限、隐私与保留期限需要单独设计。

可学习候选仅限共享角色识别或小型、受约束融合策略，不学 Practice/Pack ID 偏置。领域比例变化可能影响训练分布，训练采样与评测分组需保留来源和任务簇。重放旧任务、时间留出、未见 Pack 检验、最差组回归与版本回滚一起使用；它们降低风险，不保证无遗忘。

```text
经审核反馈 → 去重/分组 → 离线候选策略
          → 旧任务回放 + 新任务留出 + Pack 留出 + 成本检查
          → 人工批准版本 → 影子验证 → 发布/回滚
```

线上自修改、自动改 Pack 内容、自动发布策略、微调整个 encoder 均不属于首轮实现范围。产品反馈采集与学习发布需另行批准设计。
