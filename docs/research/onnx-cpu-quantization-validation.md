# ONNX CPU INT8 最小验证

2026-09-11。结论：官方 INT8 模型在本机 M4 CPU 可运行，主要收益是降低内存，速度有温和改善。小型合成检索集没有出现指标下降，但向量和排序确实变化，不能宣布量化无损或完成真实检索质量验收。

本次只增加实验和报告，未修改产品代码、生产依赖或 config，未提交或推送。[结构化结果](./onnx-validation/quantization-results.json)包含两轮性能、向量偏差和逐查询结果；[检索样本](./onnx-validation/quantization-fixture.json)可复核标签。模型和本地探针仍在被忽略的 `.tmp-onnx-validation/`。

## 固定条件

沿用[前次验证](./onnx-local-validation.md)的 Apple M4 / 32 GiB / macOS 15.7.1 arm64，Bun 1.3.8、onnxruntime-node 1.29.0、tokenizers 0.2.0，CPU 4 个 intra-op threads、1 个 inter-op thread。固定 Granite 97M R2 revision `835ad14087e140460703cf0fae09f97d469d65c2`，相同 tokenizer、CLS pooling 和 L2 normalization。

官方 `onnx/model_quint8_avx2.onnx` 为 98,247,878 bytes，SHA-256 `a6022dd8220ea6f6595562a1328ee216f4a94faa55362f2f4747c80f1e78772e`，与固定 revision 的 Hub LFS 摘要核对一致。文件名带 AVX2，但本机 ARM CPU 实际加载和推理成功；这不证明该文件针对 ARM 优化，也不证明 x86 或其他设备的性能。

## 性能：内存收益比速度收益更明显

独立进程顺序为 FP32、INT8、INT8、FP32，避免并发争抢并检查运行顺序影响。包括 tokenization、张量组装、推理及向量后处理，不含加载。每项预热 3 次，短查询 60 次、64-token 查询 40 次、单文档 20 次、batch 10 次。固定长度测试使用重复 hello，属于计算负载测试，不是真实文档吞吐承诺。

| 指标，两轮范围         | FP32              | INT8              |
| ---------------------- | ----------------- | ----------------- |
| 模型文件，十进制 MB    | 390.0             | 98.2              |
| 英文短查询 p95         | 3.22–3.27 ms      | 2.24–2.29 ms      |
| 中文短查询 p95         | 3.54–3.80 ms      | 2.91–3.33 ms      |
| 64-token 查询 p95      | 6.74–10.45 ms     | 6.87–7.42 ms      |
| 512-token 单文档 p95   | 65.37–70.63 ms    | 53.72–56.58 ms    |
| 512-token 单文档吞吐   | 14.87–16.71 条/秒 | 18.87–18.98 条/秒 |
| batch 8 × 512 p95      | 567.73–573.81 ms  | 475.30–666.60 ms  |
| batch 8 × 512 吞吐     | 14.70–15.06 条/秒 | 15.92–17.05 条/秒 |
| 运行完整负载后常驻 RSS | 1557–1705 MiB     | 888–911 MiB       |

按同轮 FP32/INT8 配对，512-token 单条吞吐提升约 13%–28%，RSS 减少约 42%–48%。64-token 和批量尾延迟并非稳定变好，不能概括成所有请求都加速。两轮结果受共享桌面负载和分配器行为影响，无功耗测量；RSS 采样也不覆盖所有瞬时峰值。

本轮 FP32 常驻 RSS 高于前次的 1.12–1.38 GiB，且超过最初 1.5 GiB 起步假设。不能再把此前内存数字视为稳定上界；正式包需重测实际负载和重复生命周期。INT8 本轮约 0.87–0.89 GiB，仅是当前进程样本。

## 数值变化不等于检索损失百分比

原有 8 组、10 个向量与 Python FP32 参考对照中，token ids/mask 仍完全一致；余弦相似度为 0.925–0.979，最低来自空输入。全部数值有限，但不满足原先 FP32 的严格数值一致性容差；这里报告偏差，不将其误写成原 parity 验收通过。

检索样本的 70 个非空文本，INT8 与 FP32 向量余弦相似度均值 0.9738、最低 0.9597、最高 0.9929。全部 1200 个 query-document 相似度的绝对变化均值 0.0314、最大 0.0796。这些值是向量和分数漂移，不能换算成“质量损失 2.6%”。固定相似度阈值的行为也不能假设不变。

## 检索效果：小样本未见下降，不能宣称无损

人工规则定义的合成样本包含 40 篇通用工程短文档和 30 个查询，其中 10 个中文查询检索英文文档，覆盖代码/错误标识和语义相近的候选。标签在该样本模型推理前固定；每个文本独立编码，用精确余弦排序，不经过 ANN。文档和查询同时使用同一种精度，不测试 INT8 查询混用旧 FP32 index。

| 指标               | FP32         | INT8         |
| ------------------ | ------------ | ------------ |
| 第一名命中相关文档 | 25/30，83.3% | 26/30，86.7% |
| Recall@5           | 100%         | 100%         |
| MRR@10             | 0.9111       | 0.9278       |
| nDCG@5，二元相关性 | 0.9341       | 0.9464       |

第一名一致率为 29/30；唯一变化是 `Should a client retry POST after a 503?`。FP32 把 GET/PUT 重试规范排第一，INT8 把带幂等条件的 POST 规范排第一。其余查询的上述标签指标相同；前五名集合平均重合 84%，说明无关候选和次序仍有扰动。

这里多答对一个问题，不能证明 INT8 质量优于 FP32。样本小、文本短、部分词面匹配明显，标签未经独立人工评审；没有覆盖真实查询分布、大规模相似文档、长上下文和无答案阈值。可靠结论只有：这批样本未观察到指标下降，量化造成的数值偏差没有直接转化成命中损失。

CPU INT8 值得保留为接入候选，尤其是内存约束场景。当前尚不足以在默认后端选型上宣布胜出，也不应直接复用旧 FP32 index；是否满足产品质量要求需在独立、冻结的真实检索评测中确认。本次不自动扩大到 FP16/GPU 实验或产品实现。

> 归档说明：选型结束后已清理 `.tmp-onnx-validation/` 中的临时模型、环境、脚本和原始日志。本文对该目录的描述为实验时状态；保留的公开证据以本文链接的结构化摘要为准。选定的 Q4_0 模型及回归参考仅留在忽略的本地验收缓存，不随仓库提交。
