# 概括视图（Practice 摘要通道）实验协议：草案

> 日期：2026-10-08。状态：**已冻结(修订 1)，运行 S 条件之前**。修订原因与披露:草案的主判定集 pilot B(lorelum issue 标题)标注后没有任何可接受目标(0/40);改用公开 issue 的 pilot C 也只有 2/40;最后改用维护者授权的 Codex 会话提示(`pilot-d`,40 条,固定种子哈希分层选取,标注者为各 Pack 一名 agent,有 10 条有目标 query)。**主判定集由 pilot B 改为 pilot D**;B、C 仅作覆盖审计(verification §26.11)。在冻结之前,pilot D 上只运行过 control、Q、Q+I 等 G1 条件(结果 5/5/5,见 verification),**S、S-dup、F 没有被运行或评分**。读者：维护者与实验实现者。这是 G1 结果之后由维护者提出的**文档侧**探索,不是研究计划里“G1 通过后才开的 G2”,也不授权生产接入、Profile 变化、schema 变化或 Pack 内容改动。基础约束沿用 [G0](./role-aligned-g0-protocol.md)、[G1](./role-aligned-g1-protocol.md)：向量余弦、非负权重、全量评分后才取 K、无词面/名次融合/候选截断、不换模型、Practice ID 不作特征、检索阶段不读 labels。

## 1. 问题

一条 Practice 的“整体是什么、什么时候用、为什么”分散在 `applies_when`、正文 `When to apply` 与 `Why` 里，现有打分只看 `task-card`（标题 + `applies_when` + stage + 反模式触发）与 `body` 分块，没有一个把这几处合在一起的整体表示参与打分。**在 query 侧、模型、其余文档视图都不变时，增加一个由 Practice 已有原文拼成的概括通道，是否改善适用性排序？**

允许的结论：无收益、退化、证据不足。

## 2. 概括视图的构造（不生成新内容）

`summary` 文本 = 按顺序、以空行连接、跳过缺失项：`title`、`applies_when`、正文 `## When to apply` 小节、正文 `## Why` 小节。只复制原文，不改写、不摘要、不加字段标签，不含 Practice ID（与生产 `joinNonEmpty` 一致）。超过生产的 384 估算 token 预算时按生产同一规则切分，多个 summary view 取最大值。冻结语料 97 条全部含这两个小节。该视图只存在于实验运行目录，**不进入生产 projection**，`SEMANTIC_PROJECTION_VERSION` 不变。

## 3. 条件（相对 control 的单一改变）

query 侧一律是生产 clause 与权重，不使用角色。设对一个 query clause，$T$ 为 task-card 通道（最佳值）、$B$ 为 body 通道（$\tfrac12$ 最佳 $+\tfrac12$ 均值）、$S$ 为 summary 通道（最佳值）、$F$ 为 `full` 通道（最佳值）。缺失通道则其余通道等分。

| 条件 | clause 分数 | 回答的问题 |
| --- | --- | --- |
| control | $\tfrac12 T+\tfrac12 B$ | 基线（生产公式） |
| **S** | $\tfrac13(T+B+S)$ | 概括通道是否有额外信号 |
| S-dup | $\tfrac13(T+B+T)$ | 对照：同样的权重移动，但没有新信息（task-card 计两次） |
| F | $\tfrac13(T+B+F)$ | 对照：整篇向量（已在索引中，当初被排除）是否比概括更好或更差 |

权重 1/3 是与生产“两通道各一半”同一原则的先验选择，**不搜索**。$S$ 与 $T$ 共享 `title` 和 `applies_when`，因此 S 会更重地计入这两段；S-dup 正是用来分开这个效应。新增编码只有 summary 文本（约 97–150 条，不超过登记的 1232 个 view 的 25% 即 308 条）；query 编码数不变。每个条件保存全部 eligible Practice 的完整排名。

## 5. 判定标准（运行前登记）

沿用 `evaluateGates` 的规则并增加归因与 hub 项。对候选 S（及报告 F、S-dup 但不作为候选）：

1. **control 复现**：独立复算对生产评分最大误差 ≤ 1e-6，且 v2 冻结指标复现（33/43/45/47、MRR 0.7637、scope 2、forbidden-before-core 1）。否则停止比较。
2. **旧集不得退化**：hit@5 ≥ 45/50，MRR ≥ 同次运行 control，scope ≤ 2，forbidden-before-core ≤ 1。任何一项不满足 → 失败。
3. **pilot B 严格改进**：有目标 query 中 `success`（前 5 含 sufficient-alternative 或全部 required-core，且无禁项）**严格多于** control；含禁项的 query 数不增加；前 5 未标注槽位数之差不超过总槽位的 10%（超过则不确定）。
4. **归因**：若第 3 项成立，只有当 S-dup 与 F 的 `success` 都**不高于** S 时，才可把收益归于概括内容；否则表述为“权重移动或整篇向量也有同样效果，不能归于概括视图”。
5. **无新增 hub**：把 pilot A 与 pilot B 的 80 条 query 合并，统计每个 Practice 进入前 5 的次数；S 的最大次数不得超过 control 最大次数的 1.5 倍，否则标记并逐例复审，不自动通过。
6. **功效下限**：pilot B 中有目标的 query **少于 10 条**时，第 3 项至多为“不确定”（G1 的 pilot A 只有 5 条，不足以得出结论）。
7. **逐例与分组**：报告每个条件相对 control 的逐例改善/回归（核心名次或 pilot 成功），按 Pack、语言、任务类型分组并给样本数；零收益或回归的小组逐例复审，不因总分通过。
8. **成本**：新增编码文本数、每 query 评分耗时（相对 control 的倍数；独立参考实现不能与生产预算比较，沿用 G1 的说明）、进程内存，按 G0 冻结预算报告，与质量分开，不折算。

综合判定：任一可判定标准未达 → **失败**；否则存在不能认定的项（功效、标注非独立、覆盖不可比）→ **不确定**；全部满足且标注独立 → **通过**。因为 pilot B 的评审者是单评审 agent，**本轮没有“通过”的路径**，最好结果是“不确定但有正向迹象”，不能作为产品接入依据。

## 6. 不会做的事

不调 1/3 权重；不在看到结果后增减条件、门槛或数据；不把旧 50 例当独立验证；不把 pilot A 的结果当作未见数据；不生成或改写 Practice 内容；不修改生产 projection、Profile、schema 或 Pack。若发现设计缺陷，先报告并重新登记版本，同时说明已被查看的结果。
