# 真实任务评测 E0 协议 v2(独立请求)

> 日期:2026-10-08。状态:**v2 草案,冻结见 §7**。依据:[真实任务评测集计划](./real-task-eval-plan.md)。替代 v1 的"上下文臂"设计。本协议不改生产检索、Profile、公共 schema 或 CLI/API,也不授权 G2/G3。

## 1. 要回答的问题

在真实协作者的独立请求上(只用本句即可理解的消息),当前检索(control)把可接受的 Practice 排进前 5 的比例是多少。判定阈值见计划 §9:成功率点估计 ≥ 85% 且 Wilson 下界 ≥ 80% 为通过。目标是为检索准确度与后续优化提供基线。

## 2. 数据

- 来源:协作者 c01 的 Codex 会话中其本人输入的用户消息,2026-07 至 2026-10。
- 形式初筛、语义判定(keep 等标签)、个人信息排除与 v1 相同,结果见 `collab-c01/judge/`。
- 候选池:keep、非 pii、`context_dependent=false`,共 1053 条。
- 抽样:种子 `20261008`,按会话 40% 划入 holdout;dev 228 条、holdout 152 条,每会话最多 5 条,共 380 条,覆盖 188 个会话。
- 文件:`collab-c01/sample-standalone-380.jsonl`、`collab-c01/queries-standalone-380.json`。

**不纳入的内容**:`context_dependent=true` 的请求(约 39%)。它们依赖上文,导出数据中没有前文与助手回复,无法作为可检索的独立查询,因此不进入本协议。

**局限**:只有一位协作者;全部为中文;项目分类大量落在 `other`;判定只来自 agent,未经人工核对。在人工校准完成前,结论只能是参考性的。

## 3. 比较与分析

- 唯一条件是 control,使用与 G0 相同的生产路径重放(`control-cli.ts replay`)。
- 每条查询对全部 eligible Practice 评分,保存完整排名后才应用 K;K 只在读取排名时取前 5。
- 指标:成功率(前 5 fullyServed 且无禁项)、any-help、禁项率、覆盖率(有可接受目标的比例)、未判定率。
- 置信区间用 Wilson(95%)。分层报告 dev/holdout 与项目(样本数 ≥ 10 才报比例)。

## 4. 标注与判定

- 标签由面板 agent 给出(三名互不可见,至少两个模型家族,多数票),每个相关标签附一句 Practice 原文引用并脚本核对。
- 人工只审理由卡,金丝雀检出率 ≥ 80%、κ ≥ 0.6 才可报"通过"。
- 通过:成功率点估计 ≥ 85%,Wilson 下界 ≥ 80%,禁项率不高于 control 既有水平。
- 边缘(点估计 80%–85%,或 ≥ 85% 但下界 < 80%):记"不确定",补样本,不放宽。
- 未通过:点估计 < 80%。

## 5. 检索阶段与标签隔离

- 检索阶段只读取冻结的查询文件、语料快照与模型,不读取任何标签。
- 排名产物与 manifest 保存后,评分阶段才读取标签。

## 6. 已知的生产行为(解释用,不修改)

`projectSemanticQuery` 把查询按标点与换行切成最多 12 个子句,每个子句权重 1。长请求会被切开并等权平均。这是生产行为,本实验不改。
