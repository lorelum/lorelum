## Why

Issue #224 观察到：默认 Lorelum 根目录（`~/.lorelum`）已存在、归当前用户所有、但权限为 `0755` 时，CLI/Hook 日志 sink 的安全检查在信任根第一跳即拒绝写入——已存在段从不修复，失败被写入路径的 catch-all 无声吞掉。该次 trace 因此没有任何持久诊断证据，也没有任何提示；事后 `lore logs --trace-id` 只能返回不解释历史的空结果。该 `0755` 触发态本身可由产品自产（LocalStore 首次变更以无 mode 的递归 `mkdir` 创建根目录，按 umask 得 `0755`）。

根因是安全不变量画错了边界："从信任根往下的每一段都必须私有"把"可安全接管"与"当前够私有"混为一谈。必须私有的是日志文件内容与文件名（含 traceId、日期）；`~/.lorelum` 的存在性与"其下有 logs 目录"不是秘密。前置实现（PR #242，已关闭）进一步证明：在同一条不变量上增加备用根会把越界行为推向用户 HOME——备用根的信任根是 HOME，walk 的第一步即校验并收紧 HOME。

本变更把不变量本身换掉，并以最小实现满足 #224 的真实需求：用户自有的 `0755` 根不再导致日志丢失；确实不能写时不影响原命令，并在当次说明；必要的安全检查与回归测试保留。每多一个分支、状态或跨包改动，都须能说清少了它会违反哪条当前需求。不引入备用根、双根扫描、持久化记录、新证据状态或协议变更；daemon 启动降级独立另行处理，不是本变更的前置。

## What Changes

- **私有性边界重画**：`~/.lorelum` 及以上只做结构检查（非 symlink、是目录、归当前用户），不看、不改 mode，绝不检查或修改 `.lorelum` 之上的任何目录；从 `~/.lorelum/logs` 起的受管段目录与受管 `.jsonl` 日志文件保持私有。
- **受管段自愈**：受管目录/文件归当前用户、非 symlink、类型正确（文件另须 `nlink === 1`）且仅 group/other 权限过宽时，写入前以只减不增的掩码收紧（`newMode = oldMode & ~0o077`）；校验与收紧作用于同一打开描述符，无法对同一对象安全收紧时拒绝该位置，不退回路径 chmod。掩码后所有者权限不足以完成写入的目标（如 `0505` 目录、`0044` 文件）不修复、不写入。自愈静默完成，不提示用户执行 `chmod`、修改路径或重跑初始化命令。
- **不触碰的目标**：symlink、类型不符、多硬链接、非当前用户所有的目标不跟随、不写入、不改动；`~/.lorelum` 下不属于日志路径的内容不被触碰。
- **当次一句报告**：本次调用确实未能持久化诊断日志时，经既有 stderr 通道报告一句已知失败类别；业务结果、错误码与 exit code 不变；Host Hook 的 raw stdout ABI 不变。信任根异主（如 `sudo lore` 后遗症）时给出聚焦实测路径的非递归修复指引。
- **观察行为零变更**：`protocolVersion` 保持 2，envelope 不加字段；`lore logs`、feedback 与 trace 投影的可观察输出一个字符都不变；事后读取只报告实际读到的证据与读取限制，不推断当时的失败原因。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `diagnostic-logging`：持久日志需求的私有性边界改为"受管段自愈 + 祖先只问结构"；新增受管日志位置自愈与当次失败报告要求。

## Impact

- **代码**：`packages/log`（受管位置判定/收紧原语、`JsonlFileSink` 接线与失败暴露）、`packages/cli`（日志 runtime 的当次 stderr 报告）。Backend、feedback、日志读端与引擎不改。
- **CLI/协议**：无协议变更。确实未能写入的调用在 stderr 多一行提示；健康路径保持安静。
- **兼容性**：`0700` 正常用户无感；`0755` 根用户从"静默丢日志"变为"正常写入私有日志"；位置不可用用户从"静默丢日志"变为"业务结果不变 + 当次一句说明"。
- **测试**：注入 stat 的纯函数单测覆盖异主等无特权进程造不出的状态；真实 fs 测试覆盖收紧/拒绝与信任根逐 bit 守卫；子进程隔离 HOME 的集成测试固定"HOME 与祖先目录逐 bit 不变"，不触碰开发者真实 `~/.lorelum`。
