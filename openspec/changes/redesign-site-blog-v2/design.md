## 设计方向

技术期刊式完整版面。高级感来自：
- 更大的留白比例与严格网格对齐；
- 标题、摘要、元数据三级层级拉开，字体仍为 Bricolage Grotesque / Manrope；
- 绿色只用于品牌舞台与焦点，不作为大面积默认背景；
- 每个边界都有理由，减少装饰性边框。

浅色与深色按 DESIGN.md 的光学配对同等设计，逐主题校验对比度。

## 索引页结构

1. 发现栏：左侧平铺分类链接（ALL 与可见分类），右侧搜索触发器；窄屏分类行横向滚动，页面不横向溢出。
2. 主稿：品牌绿舞台，图片直角（无圆角，v2.5 起），舞台只放一张图；舞台外不再套卡片。
3. 摘要区：舞台下方独立排版，正文列 ≤ 76ch，壳上限 88rem。
4. 后续条目：分隔线列表，标题为唯一交互入口，hover 仅做封面轻微缩放与背景细微变色，标题无下划线。

## 文章页结构

- 左导航与右目录保留（≥1280px 双栏、1024–1279px 仅左栏、<1024px 仅正文，目录回落 `<details>`）。
- 首屏图版与索引一致，标题层级与索引同源。
- 正文列 620–675px 不变。

## 实施顺序（每步单独提交）

1. 索引主稿与列表样式；
2. 索引发现栏与搜索触发器的版式；
3. 文章页首屏与导航/目录间距；
4. 守卫测试迁移与新增；
5. 验收与证据。

## 索引 v2.1：参考 Colorlib Original 的节奏

用户认可 Original 模板的节奏，并按推荐默认裁定：只改索引页，文章页不动；不加右侧工具栏；不照搬横线与大写；日期块不覆盖封面。

- 报头：居中 h1（headline 角色 2.5rem），不加标语。用户此前明确否决 h1 下的说明句（证据台账 §39），`blogIndexDescription` 仅保留给 meta description。（主稿标题字号在 v2.2 中改变，见下。）
- 工具栏：上下细线，lg 起分类在左、搜索触发器在右（v2.7 起；此前分类居中，贴着搜索框，用户要求改到左边）；窄屏分类行与搜索各占一行。搜索触发器保持与 docs 一致的样式（用户此前要求统一，故不改成下划线），仍打开 docs 搜索弹窗。
- 条目：封面与文字 5fr/7fr；元数据块以日期块（日、本地化月份、年）开头，其后是分类、作者与语言提示，位于标题上方，无横线、无大写、无字距。日期块不覆盖封面，因为封面角落有必要的声明文字。
- 日期：`dateTime` 保持 ISO；显示用固定语言标签（en-US、zh-CN）与 UTC，避免 SSR 与浏览器差异。
- 拒绝：社交条、订阅、轮播、标签云、广告、Instagram 条、最新文章侧栏（无数据源或重复内容，且违反 DESIGN.md 或用户此前否决）。
- 无新增动效、token 或 frontmatter 字段。

## 索引 v2.2：首稿单图，hover 浮现内容

用户要求首稿不要「一堆大字加一张繁琐的图」，改为单图，鼠标悬停才浮现内容。用户两次取消了澄清提问，以下按推荐项执行，偏离处已标明，待用户确认。

- 舞台只放一张图（v2.6 起为参照 OpenAI 开发者博客封面标准自绘的几何抽象图：柔和渐变底、居中玻璃几何体、无文字）。标题、元数据与摘要在同一阅读块内。
- 仅精细指针（`hover: hover` 且 `pointer: fine`）下，阅读块与舞台叠放并在悬停或键盘聚焦时淡入；触屏及无 hover 设备始终在舞台下方完整显示，否则这些读者看不到标题。
- 阅读块用透明度而非 display 隐藏，保留在可访问树内；标题链接仍是唯一交互元素，其 `::after` 覆盖整个条目。为此阅读块不能有 `position` 或 `transform`（否则它成为 `::after` 的定位基准，点击区域缩成阅读块大小，且静止时它因下移 3rem 而伸出图片下沿，造成悬停反复闪烁，v2.7 修复）；上滑改用 `margin-bottom` 过渡，`z-index` 对网格子项无需定位即可生效。
- 这改变了先前「主稿标题是页面最大字号」：标题降为 2xl–4xl，报头 h1（2.5rem）成为最大字。V1 的「标题为视觉中心」改为「图为视觉中心」。
- 范围仅限首稿。列表行已是图加文结构，未改；是否同样做悬浮卡待用户决定。
