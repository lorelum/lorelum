## 当前修订：2026-09-30 横向索引与搜索

- 索引继续复用 BlogShell 的边界，但 `.blog-shell--index` 在全部断点仅有一轨，不渲染 BlogSidebar。文章页三栏/两栏/单栏规则不变。
- 分类和排序保持 Link pills、44px 触达与完整 URL 状态；工具栏只挂载一次，窄屏自动换行。搜索位于桌面右侧，窄屏独立一行。首稿随索引宽度重新展开，但摘要有独立行长约束，卡片不添加第二个交互入口。
- `q` 仅接受字符串，去首尾空白并限制 200 字符；匹配阶段对文本做 NFKC、大小写与空白归一化，多个关键词采用 AND，字面包含匹配，不把输入当正则。空白查询等同无搜索。
- 两条索引路由使用已安装路由库的 stripSearchParams 中间件移除默认 newest 排序，避免重置后仍残留 sort=newest；非默认排序、分类与 q 不被该中间件删除。搜索输入受控并在已提交查询态变化时复原，不保留与返回/前进目标不一致的未提交文字。
- 服务端保留完整可见条目供分类枚举，返回分类与搜索交集的 slug。两个索引路由验证和转发 q；排序仍在过滤前完成，不改变确定性顺序或双语合并/草稿规则。
- 搜索表单是可提交的 GET form，具有真实标签与显式提交按钮；隐藏字段保留分类和排序。提交后 q 进入 URL，返回/前进恢复输入值；结果数量、搜索空态和重置入口清晰可达。
- 启用脚本时提交通过路由的类型安全序列化与客户端导航完成，数字、布尔值或 JSON 外观的输入仍保持字符串关键词，避免原生 GET 的裸值被路由 JSON 查询解析器改变类型。没有脚本时保留原生 GET 降级。输入不因查询变化重新挂载，受控值同步已提交状态，保持键盘焦点。
- 搜索服从既有预渲染边界：首次静态应答不随 q 改写，水合/客户端导航后才呈现匹配结果。无脚本提交仍可生成可分享 URL，不伪称无脚本搜索已执行。
- 用户批准仅更新索引布局、控件位置和新增 q 状态涉及的既有断言，其余守卫继续保留；新增纯模型、路由接线及浏览器搜索回路验证。

## Context

博客当前是「居中孤岛」：`main` 用 `max-w-[var(--lore-reading-width)]` 居中，索引 664px、文章页 976px（976 = 664 列 + 240 轨 + 72 间距）。后果（生产构建实测，浅色）：目录距右边缘 1440 下 241px、1920 下 481px；索引在 1920 下左右各空 621/636px，页高 900px 不能滚动。

同仓库的 docs 面已经是**通栏三栏壳**：1440 下侧栏 0–268、内容 268–1157、目录 1157–1425（距右边缘 **0px**）。本 change 让博客采用同一纪律。

## Goals / Non-Goals

**Goals**：博客索引与文章页共用一套三栏壳；左栏贴壳左缘、目录贴壳右缘；博客路由的导航有挂载态；阅读列与全部既有实测结论不变。

**Non-Goals**：放宽阅读列（664px 固定）；统一 docs 的导航行为（docs 维持全宽）；新增内容字段或路由；装饰性元素（`DESIGN.md` 的 Don'ts）。

## Decisions

### D1 壳**有上限**，不是通栏（第 2 轮修订，维护者看效果后）
第一版取通栏（与 docs 一致），结果在 1920 下中间轨道吸收全部余宽：正文 664px 落在 1328px 轨道里，**两侧各空 332px**——维护者看到的就是「文章夹在中间」。第二版给壳加 `--blog-shell-max: 88rem`（1408px）：
- 1920：壳 1408 居中 → 正文两侧空隙 **53px**，目录距右边缘 **248px**（参照页在 1914 下约 220px 的外边距，同量级）；
- 1440：上限不生效（壳=视口），目录仍在壳右缘；
- 下限：三轨 + 两个栏距 + 面内边距 = **1334px**，因此上限不得低于它，否则中间轨道比正文度量还窄、反而压窄正文（这是该数值的可证伪点）。

### D1b 博客自己的度量 `--blog-measure: 76ch`（第 2 轮新增）
维护者明确「放宽文章中间的长度」。生产 token `--lore-reading-width` 是 68ch = 664px；博客用本地别名放宽到 **76ch = 742px**（实测），**不改该 token**——docs 面消费它（`docs.css:139`），而本变更只关于博客。原计划 §5 的 620–675px 实测随之只对 docs 成立。

### D2 断点与栏宽
- `≥ xl`（1280）：`左栏 15rem | 阅读列 742px（76ch）居中 | 目录轨 15rem`，整体受 `--blog-shell-max` 约束
- `lg–xl`（1024–1279）：`左栏 15rem | 阅读列`，目录仍走既有 `<details>` 披露（计划既有决定）
- `< lg`：单栏（现状），左栏隐藏，目录走 `<details>`

算术校核（含 `padding-inline: 2rem` 与栏间距）：上限 1408 下 240+742+240+2×40 = 1302 ≤ 1408−32 = 1376 ✓；1280 下中间轨道 688 < 742，正文在该断点收窄到 688（约 70ch，可接受）；1024 两栏 240+40+713 ✓。**若不成立则不得开工**（这是本设计的可证伪点）。

### D3 左栏内容由现有数据派生，无新数据源
两段：**文章**（`listBlogPosts(lang)` 的结果，当前文章高亮，当前项用既有的 `isCurrentDestination` 判定）与**分类**（同源的 `?category=` 链接）。文章页的 loader 已经为相邻文章调用了 `listBlogPosts(post.locale)`，因此左栏不需要新的 loader 分支，只需把同一结果同时交给壳与相邻文章计算。

n=1 时左栏是「1 篇 + 3 个分类」，结构与 n=50 一致。

### D4 导航挂载态复用同一条 morph，只在博客路由创建
`useLandingNavbarMorph` 现在在 `hero === null` 时不创建 morph 触发器。本 change 让**博客屏幕传入一个触发元素**（文章头部），`hero` 存在时行为完全不变（landing），docs 不传 → 维持现状。判据：`landing-navbar__panel` 进入紧凑态（`width: min(50vw, 896px)`、`border-radius: 999px`、`margin-top: 0.75rem`），回顶部复原。

### D5 图版出栏（bounded）
文章内 `figure/table` MAY 使用中间轨道宽度而非 664px；正文文字仍受 `--lore-reading-width` 约束。必须重跑 52 格换行矩阵与 no-JS 读数，因为既有矩阵正是以「宽表格 + 不可断串」为样本。

### D6 不做的与推迟的
- 极宽屏（≥ 2560）下通栏壳的观感未定：**观察项，不在本 change 决策内**（不发明数值上限；如需要，另起一个小变更并附读数）。
- 左栏在 `< lg` 的呈现（抽屉 vs 隐藏）本 change 取**隐藏**：不新引入抽屉交互与焦点陷阱，保持改动有界。
