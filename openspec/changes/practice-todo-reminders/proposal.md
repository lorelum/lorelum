# Proposal

## Why

Agent 在规划、编码、测试和验收等关键决策时可能尚未检索所需指导，也可能忘记已读的适用 Practice。固定提示与单次行为观察不能证明遵循率提升；本变更新增贯穿任务阶段的 Skill 指导，计划工具是可选的承载方式，不是检索前提。

## What Changes

- 在设计决策、规划完成后的首次实现修改、测试设计与编写、首次选择测试运行方式、失败诊断和验收决策前，判断当前任务是否缺少适用指导；按需 semantic query、完整读取并应用，而非事后补查。
- 已有任务计划中，将已完整读取且适用于后续工作的 Practice 标识和具体检查事项关联到相关节点；不能注释时追加简短检查项，不覆盖原任务。
- 计划中已能识别未来实质性决策需要指导时，记录与任务相关的具体检索问题和时机；到节点时根据当前任务判断并执行适当的 query、完整读取和应用，而不为每次编码或测试机械添加检索。
- 无计划或无任务工具时保持现有 query/get 流程；不为 Lorelum 单独建立计划，不改变宿主权限。
- 这是新的宿主 Skill 指导，不改变 CLI、JSON、Pack、检索或 Hook 合同。行为效果需要对照验证。

## 产品说明

用户提出一项多阶段工程任务，例如“在现有导入服务中增加断点续传、保持旧客户端兼容，并完成测试和验收”。用户不需要知道 Practice ID，也不必逐阶段提醒 Agent 查询。开始时 Agent 判断设计决策需要哪些指导；规划完成后、首次实施修改前，再检查项目、语言和目标模块的编码约束是否已充分掌握。缺少指导时按当前问题运行 `lore query "..."`；准备采用候选前用 `lore get <practice-id>` 读全文，再把适用约束用于代码。

设计或编写测试前，Agent 评估恢复、并发和失败场景需要什么测试指导；首次确定测试运行方式和验收策略前，分别检查执行环境、数据隔离和验收边界。测试先行时测试节点自然先于实现节点。已完整读过且仍适用的指导直接复用，不为每次编辑或重复运行同一测试重新查询；范围、模块、故障或已知 Pack 版本变化后，针对新增问题重新判断。

有现成计划时，未来问题和时机进入相关步骤，例如“实现前查询该模块的状态恢复和编码约束”“测试设计前查询中断恢复与并发验收边界”；完整读取后可补充实际 Practice ID 和具体检查。无法安全注释时追加关联目标步骤的检查，不替换用户任务或状态；无法安全读取或维护既有计划时不改计划。无计划、无任务工具或仅要求分析的任务，不为 Lorelum 新建计划，也不执行用户未要求的实现或测试；需要指导的当前决策仍按可用工具检索。

查询返回无结果时如实说明未发现相关指导，依据现有任务合同继续；`preparing` 或失败遵循现有恢复流程，不冒称无结果。工具不可用或用户明确要求的规范不可取得时，不宣称已遵循缺失指导；独立且有充分依据的工作仍可继续，并说明一个可操作的恢复步骤。Practice 不授予安装、运行脚本、操作生产数据等权限，不适用、过期或与用户授权及更高优先级指令冲突的内容不得强制采用。用户最终看到的是实际实现、执行过的测试与未验证边界，而非仅有一串 Practice 或 todo 名称。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-integration`：在任务关键决策前按需发现、完整读取并应用指导；可安全使用宿主原生任务计划时，携带已读 Practice 的具体指导和未来实质性决策的检索提醒。

## Impact

共享 Skill 模板、生成的 portable 和宿主 Skill、双语用户文档及行为评估。
