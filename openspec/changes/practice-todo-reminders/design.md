# Design

## Context

Skill 已要求 material moment 执行 semantic query，并在采用 Practice 前读取全文。单次 omp 对照观察到候选提醒可进入 todo 并在后续节点完成，但基线也能遵循；无法据此推断因果或普遍提升。

## 用户流程

用户让 Agent 完成多步骤任务。Agent 使用现有宿主计划，读取相关 Practice 后，将影响后续工作的 Practice ID 和具体检查写入对应节点。例如：实现重试后检查某 Practice 要求对未知提交结果使用幂等或先核对。计划已存在且不能注释时追加检查项，而不是复制实施任务。到节点时根据实际任务、用户授权和更高优先级指令判断并检查工作。提醒是模型使用宿主工具的行为，不是宿主强制机制。

另一条路径是计划阶段已能识别未来的实质性决策，但尚未检索到适用指导。例如，准备开始实现某项目的编码变更时，计划可以记录“在实现前 query 本项目和语言的编码约束，读取适用结果”；准备确定验收策略时，可以记录“query 此变更的测试边界和失败场景，读取适用结果后设计验证”。这些是与具体工作关联的问题和时机，不是对所有编码或测试步骤无条件新增 query。若已确定相关 Practice ID 但尚未完整读取，可在节点记录先 get；不得将 query 摘要当作完整指导。到节点时重新判断当前任务、已有指导和适用性；已完成的检索不再重复记为待办。

没有计划或任务工具时仍正常 query/get，不仅为了提醒创建计划。未找到适用 Practice、指导不适用或发生冲突时不强制应用；查询失败按现有恢复规则处理，不伪装为空结果。原有任务和状态保持不变。

产品路径及失败处理见 [Proposal 的产品说明](./proposal.md#产品说明)。实现前、测试设计、首次选定运行方式、失败诊断和验收是分别判断指导缺口的节点，并非机械排列的工作流；测试先行可先进入测试设计。节点本身不要求无条件重复 query：已有完整且仍适用的指导直接复用，已知精确目标先 get，尚需发现其他指导时针对缺口 semantic query。此前仅凭 todo 记录未来检索不足以证明节点上发生了检索或应用。

## Goals / Non-Goals

目标是在任务关键决策前获得并应用适用指导，并在已有计划中承载后续问题、时机和已读约束；分别评估节点检索、计划写入和实际采用。非目标：改变 CLI 协议、引入持久状态或 Hook、每次编辑或测试都自动执行 query/get、保证模型遵循。

## Decisions

修改 `scripts/skill-guidance/content/skill.md.tmpl`，通过现有生成器同步宿主与 portable Skill。优先在已有步骤附注，宿主不支持时追加针对具体工作的一条检查。已读指导提醒要求完整读取且实质影响后续工作；对可预见的未来实质性决策，记录与任务相关的具体检索问题及检索时机，不为已完成查询追加任务。节点上的检索遵循现有 semantic-first 和完整读取合同，不把准备中或错误视为无结果。

现行 `agent-integration` 的 Catalog-aware targeted retrieval 要求发现时先 semantic query；本增量明确已知精确 ID 的全文读取可直接 get，仍需发现其他指导时保留 semantic-first。Skill 原有 `lore query`、`lore get` 和恢复模板是当前代码来源；本次修改只调整 Skill 指引及该合同，不改检索实现。

通用宿主缺少可用 Catalog 且当前确需发现未知指导时才 list 一次并复用；只读取已知精确 ID 时不为该读取预建 Catalog。omp Main 缺失 Catalog 时沿同一发现条件处理；子 Agent 仍不得仅因缺少 Catalog 自动补建，只有当前独立任务确需 Pack 发现时才 list。测试先行或相邻节点由同一份适用全文覆盖时复用，不为节点计数重复 query。

项目测试等非 Lorelum 故障按项目自身证据诊断，同时判断当前问题是否需要指导；只有实际的 Lorelum 调用故障才查该调用的 `diagnostics.traceId` 并使用 Lorelum 恢复流程。无 trace 的非查询故障按可见错误处理，不臆造 trace。

## Risks / Trade-offs

模型可能不调用工具、忽略提醒或产生噪声；宿主任务能力和上下文压缩行为不同。对照须区分提示来自用户、上下文还是 todo；真实宿主运行与有限样本只能证明所测情况。

评估分别观察“已读、记录、后续采用”和“计划未来问题、节点 query、完整 get、后续采用”；包括未成功写入提醒的端到端运行。对照需验证实际 todo 通道之外的用户消息、原始 Practice、工具历史、压缩摘要、文件与子 Agent 输出均未泄漏指导；无法证明隔离时只报告端到端观察。覆盖无结果、准备中或失败、结果不适用、已检索及任务变化导致的提醒失效；不以提醒或调用次数代替后续行为评分。

自然端到端对照分三组：A 为现有 Skill，B 增加阶段节点但不增加计划携带要求，C 在 B 上增加计划携带；比较 B−A 和 C−B 时保留未写提醒的运行。另行对未来检索问题及已读约束分别做来源隔离的检查点干预；只有核实可见输入、普通任务状态和外部来源可比时才讨论 todo 因果。每题每组至少五次探索性运行，固定输入和资源上限、随机顺序，分别记录不可比、失败、中断及评分错误，重复样本不视为独立题目。
